## 今日判断

今天翻完这批流，我第一个记下来的是 Boris Cherny 那条。Claude Code 团队的人讲 agent 怎么用，和外面讲 agent 能干什么，是两件事。他讲的东西落到了具体机制上：上下文怎么组织、什么时候该让人接管、哪些活适合拆给子 agent 并行跑。这种细节只有天天把自家产品当生产工具用的人才写得出来。我看下来，coding agent 这一年的实际进步，很大一块不是模型分数带来的，是这些 harness 层面的手工调优堆出来的。

第二个感受在企业侧。Levie 和 Rauch 从两头说同一件事：一头是 agent 进了公司流程以后，权限、审计、回滚变成了产品主体；另一头是部署和运行时正在被重新设计成给 agent 用的东西。我的判断是，企业 agent 短期不在模型能力上竞争，在谁先把 agent 出错以后人怎么接管做成默认能力。缺这层的产品，POC 之后就走不动，销售再猛也过不了第二轮评审。

第三点是成本。Amjad 和 Thibault 的信号放在一起看，推理单价和延迟还在往下压，但压下来的部分很快被更长的上下文和更多的 agent 轮次吃掉。builder 别指望单价下降自动救毛利，得在编排层省：缓存中间结果、强制结构化输出、能不用 agent 的地方就别用 agent。落到今天的判断，如果你在做 coding tool 或内部 agent，这周值得做的不是换模型，而是把 harness 当成核心资产来攒：模型换一家两周能做完，harness 里沉淀的失败案例和处理规则换不掉。

### 3. Levie：企业 agent 买的是权限、审计与回滚这套配套

[查看原文](https://x.com/levie/status/2125442246543814686) · 来源：Aaron Levie (@levie)

Aaron Levie 谈 agent 在企业落地时真正卡住的地方，角度一直是企业买的不是模型能力，是权限、审计、数据边界、失败回滚这一整套配套。这决定了产品形态更接近一个带策略引擎的工作流系统，而不是一个对话框。我的判断是，企业 agent 的分水岭不在模型选型，在有没有把人在环路的接管路径做成默认能力。做 To B 的人该补的是权限模型和可观测性，不是 prompt 效果。

### 4. Rauch：构建、预览、回滚要为 agent 重新设计

[查看原文](https://x.com/rauchg/status/2125320020666565096) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 谈 agent 时代的部署与运行时，落点是构建、预览、回滚这些原本为人类开发者设计的环节要怎么改。agent 提交代码的速度远高于人类评审速度，传统 CI/CD 的假设会失效，预览环境、变更粒度和回滚策略都得重做。我的判断是，这一层会变成接下来一年最实在的 infra 生意，因为它不依赖模型进步，只依赖 agent 用得越来越多这个事实。做开发者工具的团队该把部署链路按 agent 为第一用户重走一遍。

### 5. Amjad Masad：单价下降会被更长上下文和更多轮次抵消

[查看原文](https://x.com/amasad/status/2125353849057853876) · 来源：Amjad Masad (@amasad)

Amjad Masad 讨论 agent 运行时的基础设施与模型成本。Replit 同时承担模型调用成本、沙箱运行成本和用户对等待时间的耐心，他对价格的体感比纯应用层公司更真实。单价下降经常被更长的上下文和更多轮 agent 调用抵消，毛利率不会自动改善。我的判断是，成本控制得在编排层做：缓存中间结果、限制无效重试、把简单任务路由到小模型，这些比等下一轮降价靠谱。

### 7. Peter Yang 谈非重度工程用户的 coding agent 使用方式

[查看原文](https://x.com/petergyang/status/2125246815884984398) · 来源：Peter Yang (@petergyang)

Peter Yang 就 coding agent 的实际使用方式展开讨论，角度偏产品和非重度工程用户。大量新用户是通过 agent 第一次接触编程，他们的习惯和传统 IDE 用户完全不同，错误提示、预览、撤销这些交互的权重都会变。我的判断是，面向这类用户的产品不该照抄职业开发者的工作流，得重新设计反馈回路。这条适合做产品的人看，工程细节不多。
