## 今日判断

我今天更关注已经在真实工作流里跑 agent 的人在抱怨什么。Dan Shipper、Guillermo Rauch、Aaron Levie 这几条放在一起，说的不是能力上限，而是 agent 塞进生产环节后暴露的摩擦：谁批准它改文件、改完谁验、出错怎么回滚、日志能不能复盘。这比任何 benchmark 都更能说明现在卡在哪。

具体机制是验证层在变厚。多数团队给 agent 产出加一道确定性检查，测试、类型、lint、schema 校验，能过就自动往下走，过不了才交给人。所以关于 coding agent 的讨论都在往沙箱、可复现评测集、diff 粒度上挪。模型强一点弱一点，对已经跑起来的团队影响不大，瓶颈在验证覆盖率，不在生成质量。

这周如果要动一件事，我会先数自己工作流里有多少步骤是 agent 做完没人验的，那部分才是真正的风险敞口，其余能力问题等下版模型。Levie 的顺序我认为对：企业先定权限、审计和身份边界，再谈能力，这个顺序还会持续一两年，做 infra 的人应该把这一层当产品做，不是当合规附件。

### 2. Aaron Levie：企业上 agent，顺序是先权限和审计

[查看原文](https://x.com/levie/status/2119987129204047894) · 来源：Aaron Levie (@levie)

Levie 把话题拉回企业侧：agent 能不能在一个组织里跑起来，前提是身份、权限边界和可审计的操作记录，不是模型选型。这个顺序来自一线客户部署，和先追能力、后补治理的做法相反，返工成本通常落在那批先追能力的团队身上。企业 agent 接下来一两年的门槛在权限模型和日志粒度，做 infra 的人要把这层当产品做，而不是当交付前的合规附件。

[查看原文](https://www.youtube.com/@LatentSpacePod) · 来源：Latent Space

这期把 agent workflow、infra 和企业部署放在一起谈，参与者都在跑真实系统，聊编排、状态管理、失败重试和成本结构，不谈模型排行。播客里的一手架构描述往往比博文更诚实，会顺带说出哪里做得难看、哪块是临时拼的。agent infra 正在长成一门独立的工程学科，值得单独盯一条线，和 prompt 技巧混着看会低估状态与可观测性的工作量。

### 4. Guillermo Rauch：agent 需要自己的运行时，不是塞进应用当函数

[查看原文](https://x.com/rauchg/status/2119891138450755670) · 来源：Guillermo Rauch (@rauchg)

agent 需要自己的沙箱、生命周期和可观测性，而不是塞进现有应用里当一次函数调用。平台方这个表态会改变接下来一批开发工具的默认架构，尤其是启动、回滚和计费怎么定义。谁先把 agent 的部署、回滚和按用量计费做成标准动作，谁就拿到下一层的入口，这比再做一个 chat 界面重要得多。

### 5. Alex Albert 那条互动最高的帖，价值在回复区

[查看原文](https://x.com/alexalbert__/status/2119884951550386671) · 来源：Alex Albert (@alexalbert__)

### 6. Amjad Masad：coding 工具被采购的方式在变

[查看原文](https://x.com/amasad/status/2119909166764667292) · 来源：Amjad Masad (@amasad)

这条偏产品和商业侧：coding 工具在团队和公司里被采购、被使用的方式在变，不是又多了什么模型能力。Replit 面向大量本来不写代码的人，它的观察能看出需求的真实形状，专业开发者视角反而会漏掉这块。coding agent 的下一波增长不在职业工程师，而在原来根本不碰代码的人，这会逼着工具重做默认交互、错误提示和权限模型，工程师向的产品逻辑套不过去。

### 7. Boris Cherny：Claude Code 在真实团队里长成什么样

[查看原文](https://x.com/bcherny/status/2119890820186976763) · 来源：Boris Cherny (@bcherny)

Claude Code 的作者讲这个工具在真实工程团队里的使用形态：谁在用、怎么嵌进已有的 review 与发布流程、哪些环节它现在还不该碰。工具作者看到的分布比单个用户自述更完整，能说明需求往哪个方向收敛。coding agent 的形态正在从 IDE 插件收敛到命令行加仓库级上下文，权限控制和改动审查会成为主要差异化点，不是补全速度。

### 8. Swyx 给模型进展泼了盆冷水

[查看原文](https://x.com/swyx/status/2119935240202539147) · 来源：Swyx (@swyx)

Swyx 在模型话题上给了不同意见，回复数相对点赞偏高，说明触到了分歧点。这批人日常在换模型、压成本和调工具调用，他们对新版本不再兴奋，通常意味着提升集中在不解决手上问题的维度。接下来几个月的实际竞争落在推理成本、上下文管理和工具调用稳定性上，单点 benchmark 的说服力在下降，做产品的人该按自己的失败案例建评测集，而不是看发布页的对比表。
