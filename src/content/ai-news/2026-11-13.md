## 今日判断

我今天更关注把 agent 塞进真实工作流的讨论，而不是模型榜单。Dan Shipper、Aditya Agarwal 的帖子指向同一个动作：团队把 agent 当成生产流程的一环，接权限、接数据、接失败回滚。这个阶段值钱的信息不是 demo 多强，而是哪一步交给了 agent、出错后怎么收回来。

Coding agent 这边，Thariq 和 Thibault 的讨论让我更确定：生成速度不是瓶颈，反馈回路才是。agent 能不能自己跑测试、读日志、改下一版，决定它能不能进日常开发。只给更快的补全，团队两周就会回到原来的工作流。

我的判断是，接下来几周要盯产品层怎么重切 infra，而不是新模型发布。模型平台、IDE、部署平台都在往上下游伸，最后落在权限、评测、可观测性这些很土的地方。谁能把这些做成默认能力，谁就能把 agent 留在工作流里。给一线 builder 的动作：这周先给 agent 接上测试、日志和回滚，再谈接核心业务代码。

### 2. AI infra 正往产品层延伸

[查看原文](https://x.com/adityaag/status/2120578134177464356) · 来源：Aditya Agarwal (@adityaag)

Aditya Agarwal 谈了一个变化：infra 不再只卖算力或 API，而在往产品体验和交付结果上走。选 infra 时要看它能不能一起解决评测、权限、成本控制，不只看延迟和价格。判断：下一轮 infra 竞争发生在默认工作流里，谁能把复杂配置收进产品，谁就更容易被团队留下。

### 4. Coding agent 的反馈回路决定能否进日常开发

[查看原文](https://x.com/trq212/status/2120621112807866620) · 来源：Thariq (@trq212)

Thariq 讨论 coding agent 怎么进入真实开发流程。瓶颈不是一次生成多快，而是能不能自己跑测试、读报错、拿到下一轮修改信号。这个反馈回路决定 agent 是玩具还是日常工具。判断：2026 年 coding tool 的差异更多来自测试、日志和回滚设计，而不是补全速度。

[查看原文](https://x.com/rauchg/status/2120601000176439478) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 谈产品变化。AI 功能进入产品后，变化落在交互、部署和默认工作流上，不是在旧界面上加一个入口。对开发者工具来说，这会影响产品结构和发布方式。判断：竞争点会变成谁能把 AI 能力做成默认路径，同时不破坏原有可解释性。

### 7. 模型能力变化重分应用层工作

[查看原文](https://x.com/amasad/status/2120671838909194695) · 来源：Amjad Masad (@amasad)

Amjad Masad 从模型角度谈应用层变化。重点不是模型又强了多少，而是能力变化会重分应用层工作：哪些步骤交给模型，哪些留在产品代码里。这直接影响 agent 的边界设计和成本结构。判断：应用层不会消失，但会从写流程变成设计约束和验收标准。
