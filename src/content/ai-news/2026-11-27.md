## 今日判断

今天翻完候选，我留下的几条都来自每天跑 agent、写代码的人，不是发布会通稿。Karpathy 那条传播最广，我更关注他讲的上下文和 token 预算：模型把一段代码写对已经不难，难的是喂对信息，并在有限窗口内把任务做完。Thibault 和 Thariq 的内容落在产品与团队侧：coding agent 的体验差距取决于工具链怎么设计、失败怎么恢复，模型分数只占一小部分；写评测和 prompt 的人开始直接影响产品决策。

企业侧也有信号。Aaron Levie、Madhu Guru 都在讲 agent 进入真实业务系统时的摩擦，主要是权限、数据边界和审计，这些不会因为模型变强消失。Zara Zhang 的长文讲把 AI 塞进已有工作流的实际代价，包括工作量只是挪了位置、维护成本反而增加。谁肯把这些工程细节做扎实，谁的 agent 才留得住用户。

接下来几个月，我更关注 token 预算和运行环境怎么被产品化：给 agent 多少上下文、什么时候压缩、什么时候重开一轮，这些能不能做成默认行为；执行环境和回滚能不能做稳。做 coding tool 或 agent 产品的人，今天这几条里的工程细节比任何 benchmark 都更值得照着抄。

### 1. Karpathy 谈 coding agent：难点从写代码转向上下文管理

[查看原文](https://x.com/karpathy/status/2125779541952246039) · 来源：Andrej Karpathy (@karpathy)

Karpathy 的长帖有近600条回复，讨论 coding agent 跑起来后的上下文管理：任务怎么拆、关键信息留在哪一轮、token 预算怎么分配。模型把代码写对已不是主要瓶颈；模型能力拉平后，工程侧对上下文和工具调用的控制直接决定产品体验。这条可直接用作团队内部分享材料。

### 2. OpenAI 的 Thibault：Codex 更新后，用户反馈集中在工程问题

[查看原文](https://x.com/thsottiaux/status/2125784147889393806) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 发布 Codex 相关更新，回复超过3600条。互动集中在长任务稳定性、大仓库场景和用量成本，而不是模型是否聪明。这类一手反馈比 benchmark 更有信息量：coding agent 进入日常开发后，瓶颈会落到运行时、限流和成本。做同类产品的人可以把评论区当需求池。

[查看原文](https://x.com/trq212/status/2125675533761671405) · 来源：Thariq (@trq212)

### 5. Guillermo Rauch：agent 不接运行时，就停在聊天框

Guillermo Rauch 连发几条：agent 必须接上部署和运行时 infra 才能真正可用，否则停在聊天框。Vercel 的位置让他直接看到用户卡在权限、环境隔离和回滚。agent 产品竞争会从前端交互转向运行时能力；执行环境和失败恢复做稳，才接得住真实业务负载。

### 6. Madhu Guru：企业上 AI，卡在管道而不是模型

[查看原文](https://x.com/realmadhuguru/status/2125630707640783322) · 来源：Madhu Guru (@realmadhuguru)

Madhu Guru 讲企业把 AI 放进生产环境时的 infra 摩擦：数据边界怎么划、权限怎么管、成本怎么控。这类内容传播不高，但对做 to B 的人最有用，因为模型再强也绕不过这些部分。接下来一年企业侧的差异化会集中在这层管道：接入、审计、计费做得细的团队才拿得到续约。

[查看原文](https://x.com/amasad/status/2125664998454366305) · 来源：Amjad Masad (@amasad)

Amjad Masad 从 Replit 的实践出发，谈 agent 在真实开发环境里跑起来需要什么。他的视角是产品即运行时：代码生成只是第一步，后面还有依赖、部署和用户验收。大规模真实用户反馈比单点 benchmark 更能说明 agent 的可靠性上限：很多失败不是模型不会写，而是环境没准备好。
