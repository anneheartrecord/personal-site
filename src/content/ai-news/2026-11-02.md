## 今日判断

我今天更关注 Agent 落地中注意力从模型能力转向工程细节。Latent Space 播客和 Aaron Levie 讲同一件事的两面：写代码的人发现上下文管理、工具调用边界、评测回放才是每周花时间的地方；企业采购发现卡点不在模型分数，在权限、数据边界、责任归属。这意味着做 Agent 的团队瓶颈从能不能做出来，变成能不能稳定跑在别人的流程里。

我看下来，今天值得存的不是新模型消息，而是关于失败模式的内容。Swyx 讲 Agent 工作流容易被忽略的一层，和 Codex 负责人高互动帖指向同一机制：Agent 每多一个工具、多一轮循环，错误多一次复合机会。只有在自己搭的评测集上跑失败回放，才知道钱花在哪。没有这一步，产品只能靠调 prompt 反复试。

我的判断给一线 builder：这周别再比模型，把上周线上失败 case 拉出来做可回放评测集，写清权限和工具边界。这件事回报率比换更强模型高，而且能沉淀，下周下个月还能用。

### 1. Latent Space：Agent 从 demo 走向生产的卡点

[查看原文](https://www.youtube.com/@LatentSpacePod) · 来源：Latent Space

Latent Space 最新一期讨论 Agent 从 demo 进入生产的具体问题：上下文组织、长任务稳定性、工具调用边界、评测集复现线上失败、企业采购卡点。这些是团队每周要还的技术债。它讲失败模式而非能力上限；模型能力共享，拉开差距的是能否定位 Agent 在哪一步开始错。听完能拿到可操作清单。

### 2. Aaron Levie：企业 AI 的瓶颈不在模型，在流程和责任边界

[查看原文](https://x.com/levie/status/2116652002830963114) · 来源：Aaron Levie (@levie)

Levie 讲企业 AI 落地比 demo 慢的原因：卡点不在模型能力，在数据权限、Agent 动作签字、出错责任归属。这些决定产品能否通过采购，不是能否跑出 demo。做企业方向的 builder 应把它当需求文档，第一个企业功能可能不是更强推理，而是能过安全评审的操作日志和权限模型。做出来销售周期会短很多。

### 3. Swyx：Agent 工作流里被低估的一层

[查看原文](https://x.com/swyx/status/2116642586387730593) · 来源：Swyx (@swyx)

Swyx 这条指向 Agent 工作流容易被跳过的一层，回复区 156 条远超点赞数，说明戳到同行正在踩的坑。这类讨论价值在把问题从能不能做搬到怎么知道自己做错了。机制：Agent 每多一个工具、多一轮循环，错误多一次复合机会，小偏差会被放大。判断：做 Agent 的团队与其继续加工具，不如先加每一轮输出的校验点，让错误在扩散前被截住。这是今天就能改的工程决定。
