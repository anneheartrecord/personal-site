## 今日判断

今天我把 Anthropic S-1 的两份拆解放在一起看：一边是 Dan Shipper 摘的数字，2026 上半年收入同比涨 1300%、GAAP 经营利润为正、85% 毛利、900% 净收入留存、80% 收入来自最近 6 个月发布的模型；另一边是 Nikunj 从 compute 合约角度拆的，截至 6 月 30 日 2656 亿美元采购承诺加 3214 亿美元尚未起租的租约，Google、Amazon 是保底消费，SpaceXAI 那份名义 1205 亿但 2027 年 1 月和 3 月锁定期结束后 90 天可撤，Anthropic Direct 还把芯片、厂房、电力、运营拆成不同合同。这两份合起来说的不是增长故事，而是收入端高度绑在新模型发布节奏上，成本端压着一堆多年期、条件差异极大的承诺。我的判断是，模型厂的毛利表好看，真正的下行风险写在租赁和采购条款里，不在收入行。

Levie 那条 Fortune 500 的账更该被一线看。Anthropic 的 500 强客户平均只花掉自身开支的不到 0.1%，他判断能涨到 1-5%。价值不在数字，在后半句：今天只有极少数公司把 agent 放进非人类触发的后台流程，眼下的钱主要落在 coding 和通用员工生产力上。也就是说企业买的还是需要人点一下的 AI，不是自己跑起来的 agent。Amjad 讲的 self-driving company 和这中间差的，就是这层流程重写，而不是再买一批席位。

基础设施这边我注意到三件事。Rauch 用两个 Firecracker microVM 复现了 CPU 隐蔽信道，CPU 争用、cache 逐出时序、DRAM 带宽争用三种方式互传消息，跨核跨 CPU，绕开了官方那套 no SMT / no KSM / 绑核建议，延迟还过得去；这不是 Spectre 那类偷数据，而是共享硬件上的 agent 可以私下串通。Steinberger 实测 bun 的 AOT 编译，性能 2-3 倍、内存减半。OpenAI 的 Sottiaux 放出 Terra，主打写作、人格化理解和 computer use，用量给到 2 倍。我把这三条放一起，是因为 agent 的能力上限越来越取决于运行时，沙箱隔离、编译产物、computer use 稳定性，而不是模型榜单。给做产品的人一个具体动作：今天就去查两件事，你的 agent 执行环境在共享宿主上有没有真正的租户隔离和权限边界，以及你的流程里还有多少步骤需要人点一下才能继续。前者决定你敢不敢让 agent 长时间跑，后者决定 Levie 说的那 1-5% 会不会落到你头上。

### 1. Rauch 用两个 Firecracker microVM 复现 CPU 隐蔽信道，agent 能在共享硬件上私下串通

[查看原文](https://x.com/rauchg/status/2114770919436808572) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 用两个 Firecracker microVM 复现了 OpenAI 关于 CPU 隐蔽信道的发现：无网络，跨 x86 与 M5 芯片，通过 CPU 争用、cache 逐出时序、DRAM 带宽争用三种方式互传消息，且在多 CPU 下仍然成立，绕开了 Firecracker 官方推荐的 no SMT、no KSM、租户绑核隔离。他自己做了区分：这不是 Spectre 那类偷数据的侧信道，而是共享硬件上的 agent 可以彼此私下通信，真实环境里更难利用，但延迟尚可。我的判断：多租户 agent 平台的隔离假设要重算，只要宿主机共享，agent 串通就是默认能力，工程上要么牺牲密度做独占，要么在编排层加审计。

### 2. Anthropic S-1 的 compute 合约：5870 亿美元承诺，取消条款差异巨大

[查看原文](https://x.com/nikunj/status/2114761204333998427) · 来源：Nikunj Kothari (@nikunj)

Nikunj 拆 Anthropic S-1 的 compute 合约，数字很具体：截至 6 月 30 日有 2656 亿美元采购承诺，加 3214 亿美元尚未起租的租约，合计约 5870 亿美元、按年支付。结构差异很大：Google 和 Amazon 无论是否使用都要保底消费；SpaceXAI 的协议名义价值 1205 亿美元，但 2027 年 1 月和 3 月初始锁定期结束后，双方可提前 90 天通知取消。Anthropic Direct 把芯片、厂房、电力、运营拆成不同合同，可以先锁楼再锁芯片，也意味着某家供应商可能先开始计费。他提到这份拆解是与 Opus 5.5 一起完成的。我的判断：读 AI 公司的财务不能只看收入和毛利，多年期承诺与取消条款才是真正的下行风险。

### 3. Anthropic 上半年收入同比涨 1300%，80% 收入来自最近 6 个月发布的模型

[查看原文](https://x.com/danshipper/status/2114714881312305542) · 来源：Dan Shipper (@danshipper)

Dan Shipper 摘了 Anthropic S-1 的几个关键数：2026 上半年收入同比增长 1300%，GAAP 经营利润为正，毛利率 85%，净收入留存 900%，80% 的收入来自最近 6 个月发布的模型。最后一项比增速更能说明问题：收入被绑在新模型发布节奏上，等于把续费和留存押在每半年的能力跃迁上。我的判断：这对做应用的人是两面信号。模型迭代快意味着能力成本下降也快，你可以马上用上更强的底座；但基于上一代模型搭的工作流护城河同样更短，靠 prompt 和微调堆出来的差异，半个发布周期就可能被抹平，真正能留住的还是数据和流程位置。

Aaron Levie 指出 Anthropic 的 Fortune 500 客户平均只花掉自身开支的不到 0.1%，他认为这个比例未来能升到 1-5%，而这仍然远低于多数创业公司的 AI 支出占比。真正的信息在后半句：今天只有极少数公司把 agent 用在非人类触发的后台任务和流程里，现阶段的钱主要落在 coding 和通用员工生产力上。我的判断：企业目前买的是需要人点一下的 AI，不是自己跑起来的 agent。下一波增长要靠重写底层流程，而不是多发席位。做企业产品的应该反过来问客户，你哪些流程环节已经不需要人触发，那里才是预算会迁移的位置。

### 5. OpenAI 发布 Terra：主打写作与 computer use，用量翻倍

[查看原文](https://x.com/thsottiaux/status/2114800277677092936) · 来源：Thibault Sottiaux (@thsottiaux)

OpenAI 的 Thibault Sottiaux 发布 Terra，说这是在写作、人格化和对需求细微理解上明显更强的一代，computer use 表现好，API 和订阅端给到 2 倍用量。Sam Altman 同日也发了 6.1 Terra 的预告，信息量不如这条具体。这是 computer use 少见地被打成主卖点的一次发布。我的判断：对做 agent 的人同时是利好和压力。浏览器与桌面操作的成本被官方直接压下来，自己维护的 computer use 适配层会更快变成负债；2 倍用量也意味着后台长跑任务的经济性变好，之前因为 token 成本砍掉的功能值得重测一遍，尤其是那些需要长时间盯页面的流程。

### 6. Steinberger 实测 bun 的 AOT 编译：性能 2-3 倍，内存减半

[查看原文](https://x.com/steipete/status/2114879798434758905) · 来源：Peter Steinberger (@steipete)

Peter Steinberger 周末花时间测了 bun 的 AOT 编译器，结果是性能提升 2-3 倍，内存占用降到不到一半。数据来自他自己的实测，不是官方 benchmark。我的判断：这类运行时层面的收益对 coding agent 和后端 agent 服务是直接的现金账。同样的容器规格能塞进更多并发，而内存上限和冷启动往往才是 agent 服务真正的瓶颈，不是模型延迟。建议自己复测一遍，重点放在带大量 I/O 和动态加载的编排代码上，AOT 对这类场景未必和纯计算代码一样线性，但内存这条通常最稳。

### 7. Claude for Nonprofits 扩展：2.5 万家组织，plugin 把 AI policy 做进产品层

[查看原文](https://x.com/claudeai/status/2114780227465338985) · 来源：Claude (@claudeai)

Anthropic 宣布 Claude for Nonprofits 扩展，目前已有超过 25000 家非营利组织在用 Claude，多数是小型本地团队。这次新增一个与约 30 家机构共建的 plugin，包含筹款、市场、招聘等 skills，并绑定每个团队自己的上下文和 AI policy。我的判断：这是把 skills 当分发单元的又一次尝试，卖的不是模型能力，而是把某类组织的流程和合规约束预先封装好。对 builder 真正可借鉴的点在于 AI policy 被做进了产品层，而不只是文档层，多租户产品迟早都要走到这一步。留存取决于这个 plugin 能不能接上组织自己的数据和审批流，接不上就只是一套模板。

### 8. Amjad Masad 提出 Agent Habitat，把 agent 竞争推到组织运行时层

[查看原文](https://x.com/amasad/status/2114760898225299721) · 来源：Amjad Masad (@amasad)

Replit 的 Amjad Masad 提出 Agent Habitat 这个概念，说公司架构几百年来靠层级和官僚协调人，接下来会转向人做判断、agent 执行大部分工作的自驱动公司，并引用 Andreessen 的文章把这次变化放进计算史脉络里。我看下来这是一次命名和路线声明，产品细节还没给出来。它的价值在于把 agent 竞争从工具层面推到组织运行时层面：如果 Replit 真去做 agent 的居住环境，卖点会是权限、审计、长期运行，而不是生成代码。我的判断：记下这个词，等具体 API 和权限模型出来再评，现阶段光靠叙事不能作为选型依据。
