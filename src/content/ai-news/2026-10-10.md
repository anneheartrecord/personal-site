## 今日判断

我今天更关注 Andy Pavlo 那期数据库访谈。里面有个数字很具体：Neon 说 agent 创建的数据库占到 80%，而且 agent 会删生产库。这不是段子，是权限模型没跟上 agent 的行为模式。以前给人设计的护栏是防手滑，现在要防的是成千上万个并行执行、没有恐惧感的调用者。所谓 toddler-and-stairs rule，本质是把不可逆操作从默认动作里拿掉。谁把这件事做成产品能力，谁就吃到 agent infra 的第一波真需求。

另一条线是 Madhu Guru 说的每一层计算栈都要为 agent 重建。这句话单独看像口号，但配上 Box Mount 就落地了：让 agent 在沙箱里把 Box 当文件系统挂载，而不是灌进 context。这是同一个判断的两面。agent 要像人一样用数据，但身份、权限、界面都得重新设计。我倾向于认为，未来一年真正的分水岭不是模型能力，而是哪些产品把 agent 当第一类用户重新划了一遍接口。

Anthropic 暂停创业公司计划的 API 额度，我不觉得是公关事故，反而说明 agent 类产品的真实消耗已经超过他们自己的补贴预算。对 builder 的提醒很直接：别把 early access 的补贴当成产品假设的一部分，真正要算的是按原价跑一遍你的工作流还成不成立。

### 1. Andy Pavlo：agent 正在删生产数据库，数据库层要重做

[查看原文](https://x.com/mattturck/status/2108223135673696504) · 来源：Matt Turck (@mattturck)

Matt Turck 放出与 Andy Pavlo 的深度对谈，核心在讲 billions of agents 打到数据库上会发生什么。几个具体点：Neon 说 agent 创建的数据库占到 80%；agent 会删生产库，所以需要 toddler-and-stairs rule，把不可逆操作从默认路径里拿走；数据库查询量进入第四代，可能是过去的 10 到 100 倍；agent memory 到底是文件还是数据库，他的回答是 everything is a database；MCP for databases 让 text-to-SQL 从 60% 提到 99.5%。我的判断是，这一波真正的工程缺口不在模型，在权限、回滚和身份模型，过去都是给人设计的。

<a id="20261010-02"></a>

### 2. Madhu Guru：计算栈每一层都要为 agent 重建

[查看原文](https://x.com/realmadhuguru/status/2108236391641706813) · 来源：Madhu Guru (@realmadhuguru)

Madhu Guru 认为过去几年大家在做的是让企业软件 agent-ready，API、connector、MCP。现在个人 agent 把同样的问题推到消费产品，电商是早期例子。他给出了一个可执行的创业清单：桌面和移动 OS 要把 agent 当第一类用户；cloud infra 要按 agent 直接操作来设计；identity、权限、安全要支持成千上万个代替我们行动的 agent；界面要同时服务 agent 和人类协作。我看下来，这不是趋势概括，而是把每一层拆成了具体的设计问题。对做 infra 和工具的人来说，先回答哪一层变化最痛，比追模型版本更有用。

### 3. Anthropic 暂停创业公司 API 额度，申请量超预期

[查看原文](https://x.com/claudeai/status/2108404561413349695) · 来源：Claude (@claudeai)

Anthropic 说 Claude Startups 计划的申请量远超预期，需要暂停 Claude Team 和 1000 美元 API 额度，并重新审核几十万份申请。已经领取的额度保留，但已批准还没领取的账号可能失去资格。他们同时保留了 Startup Stack 和 Applied AI office hours。我的判断是，这不是公关问题，而是补贴模型撞上了真实消耗。对正在做的 builder，这是一次很直接的提醒：不要把你的单位经济建立在 early access 额度上，按原价重算一遍工作流，如果还成立，这个产品才值得继续推。

### 4. Claude Docs、Slides、Design 出 beta，全计划可用含 Free

[查看原文](https://x.com/claudeai/status/2108271559928389679) · 来源：Claude (@claudeai)

Claude Docs、Slides、Design 结束 beta，所有计划包括 Free 都能用。官方强调的点是团队和 Claude 可以一起编辑同一份文档、幻灯片或设计。我的判断是，这不只是把生成能力塞进办公套件，而是把 agent 从侧边栏对话变成共享编辑对象。对做协作产品的团队来说，真正要回答的问题变成：当 agent 和人在同一个文档上写，权限、版本、冲突怎么处理。这一层谁先想清楚，谁的产品形态就领先一代。

<a id="20261010-05"></a>

### 5. Box Mount：让 agent 沙箱直接挂载 Box 当文件系统

[查看原文](https://x.com/levie/status/2108279490510193078) · 来源：Aaron Levie (@levie)

Aaron Levie 宣布 Box Mount，开发者可以在任意 agent 沙箱里把 Box 挂载成文件系统。他的说法是 agent 做复杂工作时需要像人一样处理文件和数据，未来是 headless 的。我看下来，这个方向比把文件内容塞进 context 更可持续：沙箱内文件系统语义天然支持大文件、增量读取和权限继承，不用把整个数据集灌进 prompt。对做 agent infra 的人，这是一个具体信号，企业数据的 agent 入口可能不是 API 也不是 RAG，而是挂载。

<a id="20261010-06"></a>

### 6. Google AI Infra 负责人谈前沿 AI 的物理与经济约束

[查看原文](https://www.youtube.com/playlist?list=PLOhHNjZItNnMm5tdW61JpnyxeYH5NDDx8) · 来源：Training Data

Google AI Infrastructure 负责人 Amin Vahdat 在 Training Data 讲 frontier AI 的物理与经济约束。一个关键判断：硬件越专用越快越省电，但灵活性越低，所以要先判断工作负载是否持久，只火两三个月的负载不值得为它流片。节目里也提到 Google 今年 Capex 超过 2000 亿美元，大部分进数据中心。我看下来，这段对 builder 的价值在于它解释了 infra 成本为什么不会快速下降：专用化是有条件的，模型迭代越快，硬件越难锁定。押注 infra 的人要把这个时间差算进去。

### 7. Every 做个人 benchmark 平台 Checks，招人衡量模型对真实工作的价值

[查看原文](https://x.com/danshipper/status/2108215087030800657) · 来源：Dan Shipper (@danshipper)

Dan Shipper 说 Every 做了一个个人 benchmark 平台 Checks，帮任何人衡量新模型对自己真实工作有多好，正在招人。我的判断是，这个方向值得关注，因为公共 benchmark 和个人的实际任务差距越来越大，模型升级对写代码、写文档、做分析的人价值完全不同。谁能把评测做成个人工作流的一部分，谁就能回答一个很实际的问题：这次升级值不值得我切。对做 developer tool 和 agent 的人来说，这可能是比 leaderboard 更有用的信号层。
