## 今日判断

我今天主要看 coding agent 这几条。Boris 和 Thariq 讲的是同一件事：模型把代码写出来只是第一步，决定完成率的是 harness——上下文怎么裁、工具调用粒度多细、agent 什么时候停下来问人。这些默认行为来自产品作者在自己仓库里的长期磨合，benchmark 里体现不出来。我的判断是，coding tool 这一层的竞争已经不在模型接入，而在谁的默认约束更稳。

企业 agent 这边，Levie 仍然把瓶颈放在权限和审计上，卡点在 POC 到生产这一段。客户现在问的不是模型能力，而是 agent 能不能用现有身份系统读写真实数据。Rauch 从 infra 侧说的是同一件事的另一面：给 agent 用的 runtime 要重写冷启动、超时、幂等这些默认假设，因为调用者不是人。两条合起来看，agent 的基础设施面正在从云服务里独立出来，变成单独要采购的一块。

Ryo Lu 的产品视角也值得留意：agent 输出不确定，界面要处理的是信任和可控——过程是否展示、失败怎么回退，这些是设计决策而不是模型决策。

落到一线，我今天的建议是：别追着模型更新重写架构，先把自己 agent 的停止条件、权限边界和反馈循环定下来。这三件事决定产品能不能被真正用起来，而不是停在演示视频里。

### 1. Claude Code 作者谈 coding agent 的真实约束：问题不在写代码

[查看原文](https://x.com/bcherny/status/2115491259381072269) · 来源：Boris Cherny (@bcherny)

Boris Cherny 是 Claude Code 的作者之一，这条拿到 2400+ 赞，高于他平时的分享。他讲的是 coding agent 在真实仓库里的行为约束：模型能不能写出代码不是关键，agent 跑起来之后怎么控制上下文、怎么界定一次任务的边界、什么时候该停下来问人。这些经验直接对应 harness 的设计取舍：工具调用粒度、子 agent 拆分方式、状态在步骤之间怎么传递。对写 coding tool 的人来说，这比 benchmark 有用，因为它是产品作者在自己的仓库里磨出来的默认行为。判断：coding agent 的竞争已经从模型能力转到 harness 和上下文管理，先把这套约束做成默认行为的一方，完成率更稳。

### 3. Levie：企业 agent 卡在权限和数据边界，不是模型能力

[查看原文](https://x.com/levie/status/2115516370695987435) · 来源：Aaron Levie (@levie)

Levie 讲的是企业里 agent 落地的瓶颈：模型能力已经越过可用线，卡住的是权限、数据边界和审计。agent 要读写真实系统，必须先解决身份和授权，否则只能停在演示阶段。这和 Box 自己的产品路径一致，是从客户现场反推出来的判断。判断：2026 年企业 agent 的采购会越来越像买安全和身份系统，而不是买模型；还没把权限模型当一等公民的团队，会在 POC 转生产这一步被卡住。

### 4. Rauch：给 agent 用的 runtime 需要重写默认假设

[查看原文](https://x.com/rauchg/status/2115539426684408300) · 来源：Guillermo Rauch (@rauchg)

Rauch 讲的是 AI infra 层：agent 运行需要新的原语，包括沙箱、长任务的状态持久化、可观测性。过去给人用的 serverless 假设会被 agent 反向改写——调用者从人变成程序，冷启动、超时、幂等这些默认设定都要重来。判断：agent runtime 会从现有云服务里独立出来，成为单独的产品面，先定义清楚这层抽象的一方，会定下后面几年的接入标准。

<a id="20261030-05"></a>

### 5. Ryo Lu：agent 产品的界面问题是信任和可控感

[查看原文](https://x.com/ryolu_/status/2115683228027912634) · 来源：Ryo Lu (@ryolu_)

Ryo Lu 从设计端看 agent 产品形态的变化：界面从确定性的操作面板变成结果导向，设计要处理的是不确定输出下的信任和可控感——用户能不能看到过程、能不能中断、错了怎么回退。这部分最容易被低估，同一个模型，过程透明度和失败回退做得好不好，直接决定用户敢不敢把它接进真实工作流。判断：产品团队应该把它当成和模型选型同等优先级的事，而不是上线前补的交互稿。

<a id="20261030-06"></a>

### 6. Amjad Masad：coding agent 的胜负手在反馈循环速度

[查看原文](https://x.com/amasad/status/2115565072734888447) · 来源：Amjad Masad (@amasad)

Amjad 谈的是 coding agent 和托管运行环境的关系。Replit 一直把编辑、运行、部署放在同一个环境里，agent 出现后这个选择的优势被放大：agent 要能真正跑代码、看到报错、再改，闭环越短，一次任务的成功率越高。判断：coding agent 的胜负手在反馈循环速度，能不能在真实运行时里闭环，比模型强一点弱一点更有决定性；自己做 agent 工具的团队，沙箱和运行时不能外包给延迟不可控的第三方。
