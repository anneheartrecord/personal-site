## 今日判断

今天看完一圈，最直接的体感是：AI 正在把“自动化”推向那些需求没有上限的领域，所以它没有像很多人预想的那样消灭岗位，反而在制造新岗位。Aaron Levie 那条关于预测落空的推文，我认同他的判断——自动化进入非有限需求领域后，人的角色不是被替代，而是变成监督和扩展价值的操作员。这跟我观察到的 Replit、Codex 这类产品的走向一致：它们不是要把人踢出流程，而是在创造 agent operator、FDE 这类新工种。

另一个让我停下来的是 Peter Steinberger 对上游 PR 流程的吐槽：你的 agent 改了代码，对方还要求你 ping 自己的 agent 再改一轮，然后他们的 agent 再合并——这中间全是 agent 之间的异步等待，流程反而比人直接改还慢。这说明 agent 协作的协议还没定型，现在大家不过是把旧的 review 流程硬套在 agent 上，真正高效的 agent-to-agent 工作流还在早期。

我的判断是：接下来半年，值得盯的不是模型能力还能涨多少，而是 agent 之间怎么定义交接、反馈和验收的标准。谁能先解决 agent 协作的协议层，谁就能吃到下一波红利。

### 1. Levie：按能力再涨几个数量级来规划你的产品

[查看原文](https://x.com/levie/status/2097189559712837770) · 来源：Aaron Levie (@levie)

Levie 提醒创业者：AI 进展太快，你构建产品时应该假设未来模型能力和 token 量会有几个数量级的提升。最好的机会是：今天用 barely possible 的技术给客户创造价值，但你的完整使命在现有技术下几乎不可能。很多产品需要数量级更多的数据处理，目前经济上几乎不可行；或者模型能力还远未达到需求。现在就应该为这些场景而建。

### 2. AI 岗位预测正在反常识：自动化反而创造岗位

[查看原文](https://x.com/levie/status/2097004960307449937) · 来源：Aaron Levie (@levie)

Levie 指出，AI 的岗位影响与许多人预想的相反，原因是 AI 将自动化带入了需求没有上限的领域。AI 让公司能做更多事，但 agent 仍然需要人类操作和监督来产生价值。AI 不仅没有取代工程师、律师等理论受影响最大的岗位，还创造了新岗位：网络安全、FDE、agent 操作员、非软件领域的工程师等。这个趋势是否反转还不清楚，因为 AI 不断打开新的需求领域。
