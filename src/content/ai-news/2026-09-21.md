## 今日判断

我今天更关注的是 Aaron Levie 那句话背后的机制变化：agent 成为消费者之后，产品竞争的对象从人变成 agent。Muse 这类产品要求你把任务完整交接出去，agent 必须能操作你的工具、走你的 CLI、在你站点里完成交易。这意味着过去围绕转化率、按钮位置、用户注意力做的优化，接下来要让位给「agent 能不能顺利跑通」。谁能把 agent 的调用路径、权限和支付做得最顺，谁就会被最多 agent 选中。我的判断是，面向 agent 的可调用性会成为下一个基础设施赛道，而不是再做一个更好的 UI。

第二件事是 Nikunj Kothari 说的那套投资人也要写代码的逻辑，我觉得这对 builder 比对 VC 更有用。他每天花两小时读 repo、跑新工具，理由是只有亲手用才能判断模型能力、infra 缺口和 harness 层会怎么长。这和我看到的趋势一致：现在分辨一个 AI 产品靠不靠谱，看 demo 没用，要看他有没有把真实工作流接进去、有没有暴露架构和失败复盘。二手评论已经严重贬值，一手实践记录才值钱。

还有一条值得单独拎出来：Aditya Agarwal 说在 Gemini、OpenAI、Anthropic 这轮 agent 能力扩张之后，他几乎可以确定有些大公司已经被国家级攻击者渗透而自己还不知道。这不是耸动，而是 agent 拿到更多工具权限后的直接后果。权限边界、审计日志、agent 身份这几个东西，现在几乎没有产品认真做。我的判断是，agent 安全会从合规话题变成产品功能，谁先把可审计、可回滚的 agent 权限做出来，谁就拿到企业单。

### 1. Aaron Levie：个人 agent 时代，产品要开始为 agent 而建

[查看原文](https://x.com/levie/status/2101427997597446636) · 来源：Aaron Levie (@levie)

Levie 说个人 agent 是「build something that agents want」的终极形态。像 Muse 这样的产品，用户会把任务整段交出去，agent 必须能用你的工具，或者用自己的一套完成操作：走你的 MCP 或 CLI、顺畅导航你的站点、完成交易。竞争对象不再是用户的注意力，而是 agent 的选择。因此那些让 agent 订餐、做电商交易、订机票、接入本地经济和数据最顺的工具，会被用得最多。他认为这是自 App Store 以来消费科技最大的一次机会和洗牌。我的判断是这条对 builder 的门槛判断最实在：接下来要做的不是更好看的界面，而是更可靠的 agent 调用路径、权限和支付。

### 2. Nikunj Kothari：不亲自写代码，就判断不了模型下一步会怎么走

[查看原文](https://x.com/nikunj/status/2101340098356990058) · 来源：Nikunj Kothari (@nikunj)

Kothari 说他每天花约两小时编程、做副项目、试新仓库，总有人问他一个 VC 为什么还做这个。他的回答是这一轮变化太快，不亲手做就无法知道下一步会发生什么。他把理解拆成三层：读技术论文理解模型能力边界，看工具缺口理解 infra，理解 harness 能力理解应用层怎么长出自主公司。他承认可以靠和研究者、builder 聊天来学，但还是自己动手最直接。我看下来这条的价值在于它把「泡在 AI 里」变成了可执行的动作，而不是一句态度。对一线 builder 来说，这也是为什么失败复盘和技术细节比二手评论更值钱。

### 3. Aditya Agarwal：agent 权限扩张之后，大公司被渗透可能已经是默认状态

[查看原文](https://x.com/adityaag/status/2101426570850451914) · 来源：Aditya Agarwal (@adityaag)

Agarwal 说在看 Gemini、OpenAI、Anthropic 这轮 agent 能力公告的狂潮之后，他几乎可以百分百确定已经有一些大公司被国家级攻击者渗透，而且自己还不知道。他没有展开技术细节，但指向很明确：agent 拿到更多工具权限、更多系统访问、更多自动化执行能力之后，攻击面同步扩大，而企业现有的审计和权限模型没跟上。我的判断是，这对做企业级 agent 的人不是恐吓，而是产品需求信号。可审计、可回滚、带身份边界的 agent 权限层，会从合规要求变成实打实的企业采购理由，谁先做出来谁先拿到单。

<a id="20260921-04"></a>

### 4. Peter Yang：用 markdown 文件加一个 skill 做私人推荐系统

[查看原文](https://x.com/petergyang/status/2101503916743749878) · 来源：Peter Yang (@petergyang)

Yang 说他用一个简单的 markdown 文件保存自己对电影、剧集和书的评分，配一个 /tastemaker skill，每周自动查新上线和他没看过的内容，给出相关性很高的推荐，并问要不要开源。这看起来是小事，但它展示了一个正在成形的模式：个人数据留在本地文件，agent 用可复用的 skill 读取并定期执行，替代掉一个独立推荐 App。我的判断是，这类「文件即数据库、skill 即产品」的用法会越来越多，对做 agent 工具的人是一个提示，要支持用户把自己的上下文文件直接接进来，而不是再建一套封闭的偏好系统。

### 5. Richard Socher 谈递归自我改进：能模拟的东西 AI 都会解掉

[查看原文](https://www.youtube.com/@DataDrivenNYC/videos) · 来源：The MAD Podcast with Matt Turck

这期 MAD Podcast 里 Matt Turck 对话 Richard Socher，主题是递归自我改进，也就是 AI 造更好的 AI。Socher 刚为 Recursive 融资 6.5 亿美元，并出了新书 The Eureka Machine。播客里他给出一句很硬的判断：任何你能模拟的东西，AI 最终都会解掉，而这会把人带进递归自我改进的循环。他也说我们离各类智能的真正上限还很远。我的判断是，这条不是当天新闻，但值得放进长期视角：当一个明确做 RSI 的公司拿到这种量级的钱，接下来模型研究、算力和科学发现工具的重叠会变得更具体，做工具链和评测的人要开始盯着这条线会先在哪落地。
