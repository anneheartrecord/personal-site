## 今日判断

今天我把 Claude Marketplace 这条放在了最前面，不是因为 Anthropic 又发了个产品，而是因为它改的是采购路径。企业手里的 Anthropic 承诺消费额度，现在可以直接拿去换 Cursor、FactoryAI、Vercel、CrowdStrike 这些第三方 Claude-powered 产品。这意味着做 Agent 和 Coding Tool 的团队，多了一条不靠自建销售团队就能进大客户的通道。以前中小企业做企业单，最卡的不是产品，是客户的预算流程；现在客户的预算已经在 Anthropic 账上了，你要做的是让自己被列进那个目录。

Aaron Levie 今天两条我都很认同，尤其那条讲 AI 扩散比想象慢的。他的核心机制是 corporate physics：数据要先准备好、流程要重新设计、组织要达成共识，然后还得等真实世界里的人回你邮件。这解释了一个我最近一直想的事——模型能力涨得很快，但我在客户现场看到的落地速度，被这些非模型因素堵得死死的。他又补了一句 coding agent 会让工程师杠杆变大、需求变多，这跟前面不矛盾：code 变便宜，被压抑的软件需求才会释放出来。

Guillermo Rauch 那条价格数字也值得记一笔。六个月里 8 次降价和费用结构调整、16 个模型打折，这种节奏下，做 Infra 和中间层的团队要重新算自己的毛利模型，别把定价建在一个会持续下滑的 token 单价上。另外 Peter Steinberger 说他把团队内部定制工具换成了 dashboard 和插件，这条小但真实，是 agent 工具链开始吃掉内部工具的信号。

### 1. Claude Marketplace 把企业承诺消费变成第三方产品的采购通道

[查看原文](https://x.com/claudeai/status/2097718980437831935) · 来源：Claude (@claudeai)

Anthropic 上线 Claude Marketplace，首批合作方包括 CrowdStrike、Cursor、FactoryAI、Gamma 和 Vercel。企业在 Anthropic 上的承诺消费额度，可以直接用来购买这些 Claude 驱动的第三方产品和 agent。这事有意思的地方不在产品清单，而在预算入口：以前中小团队卖企业，最难的是挤进客户已经冻结的采购流程，现在客户的预算已经落在 Anthropic 账上，你要做的只是让自己出现在那个目录里。对做 Agent 和 Coding Tool 的 builder 来说，这是继云市场之后又一条低成本进大客户的路径，但也意味着你要接受平台成为你和客户之间的中间层。我的判断是，接下来会有更多模型厂商复制这个结构，谁能拿到企业承诺消费的入口，谁就掌握了分发。

### 2. Aaron Levie：AI 扩散慢，是被公司物理约束卡住的

[查看原文](https://x.com/levie/status/2097738533297689012) · 来源：Aaron Levie (@levie)

Levie 在解释为什么模型能力涨得这么快，GDP 上却看不太出来：扩散速度比大家想的慢得多。他把原因归到 corporate physics——先把数据整理进管道、重新设计流程、组织内部对齐新工作流该怎么跑，这些做完之后，还要等真实世界的速度，比如客户回提案、项目拿许可、药物研发几年才到消费者。他还提到很多日常 AI 用例对 GDP 是净中性的。这条的价值在于它把 AI 落地慢的锅从模型能力挪到了组织与现实约束上。我的判断是，做企业 Agent 的团队应该把精力从证明模型多强，转到帮客户处理数据准备和流程再设计，那才是真正卡住扩散的地方。

### 3. Aaron Levie：code 变便宜，会释放被压抑的软件需求

[查看原文](https://x.com/levie/status/2097920810543468551) · 来源：Aaron Levie (@levie)

Levie 列了一串 coding agent 的用途：全新品类工具、以前付不起软件的公司、用 agent 做安全防护、生命科学研究自动化、复杂数据流处理、老系统升级，并说这会导致软件更有用、工程师杠杆更高，反而需要更多工程师而不是更少。这跟前面那条 AI 扩散慢不矛盾——正因为真实世界有大量被压抑的软件需求没被满足，code 变便宜才会把它们放出来。我的判断是，这条对一线 builder 的意义在于：别只盯着用 coding agent 替代现有开发，去看那些以前因为成本太高而根本没被立项的软件，那才是增量所在。

### 4. Vercel 半年 8 次降价、16 个模型折扣，Infra 定价要重新算

[查看原文](https://x.com/rauchg/status/2097828203658383674) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 说过去六个月里 Vercel 做了 8 次降价、费用移除和结构调整，外加 16 个模型的折扣，并且还会继续。这条本身很短，但数字有用。它说明 AI 推理和托管层的价格下行不是偶发，而是被持续执行的策略。对做 Infra 和中间层的团队来说，这意味着不要把毛利模型建在一个会持续下滑的 token 单价上，得想清楚自己的定价里哪部分能扛住上游降价，哪部分应该主动让出去换规模。我的判断是，接下来能活下来的中间层，要么锁定不可替代的工作流，要么把降价当作获客武器而不是威胁。

### 5. Peter Steinberger：团队内部定制工具正在被 dashboard 和插件替代

[查看原文](https://x.com/steipete/status/2097880507753382201) · 来源：Peter Steinberger (@steipete)

Steinberger 说他两个月前推动的 dashboards 和 mini-apps，现在已经替换掉团队围绕 OC 建的很多定制工具，所有东西都变成团队服务器上的一个 sidebar 条目、dashboard 或插件。这条信息量不大但很真实，它展示了一个正在发生的模式：agent 和插件体系开始吃掉过去需要单独写的内部小工具。对做开发者工具的人，这是个信号——你的竞品可能不是另一个 SaaS，而是客户自己用 agent 拼出来的插件。我的判断是，内部工具的形态会从独立应用收敛成宿主平台里的一个入口，做工具的团队要么成为那个宿主，要么成为最容易被装进去的插件。

### 6. Codex 与 ChatGPT Work 的额度重置 bug，官方给受影响用户补发

[查看原文](https://x.com/thsottiaux/status/2097752790177370535) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 说当天早上出现一个 kerfuffle：一些已存的额度重置在 ChatGPT Work 和 Codex 使用时没有完全生效。在受影响时间窗口内使用过的用户会再拿到一次重置，并收到道歉邮件。这条值得留意不是因为 bug 本身，而是它暴露了按额度计费的 coding agent 产品里，计量和配额系统本身就是信任基础设施。做类似产品的团队应该把它当案例：配额出错时，主动补发比解释更省事。我的判断是，随着 coding agent 进入企业日常工作流，这类计量事故的代价会越来越高，配额系统的可靠性会变成和模型质量同等重要的竞争点。
