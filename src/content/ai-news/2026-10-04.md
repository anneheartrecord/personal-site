## 今日判断

今天看完这批候选，我最在意的不是某个新模型，而是产品形态在往一个方向收：AI 开始从聊天框里走出来，变成一直在线、持续学习你工作方式的伴随层。Sam Altman 说 dot 是他最喜欢的 OpenAI 产品，而且每天都在变好，因为它越来越懂他的工作流和风格——这句话的机制在于它是持续积累的上下文，而不是每次重新提问。Garry Tan 讲 GBrain 也落在同一个点上，他要的是像 web 一样原生、24 小时在线的个人 agent，不是聊天机器人里的一个功能。

第二个更工程化的信号是并发 agent 开始互相协调。Garry Tan 提到 Capy 的 cross-session coordination：他的协作者 Sina 发起一轮修改，会主动避开他在多个 Capy 线程里已经在做的事，而且跟具体模型无关。这比单 agent 跑得久重要得多——一旦多个 agent 共享同一份工作状态，任务分配、冲突避免、状态同步就会变成真正的 infra 问题，现在这块还在很早期。

Coding 这一侧也在出真实的替代案例。Peter Yang 说他一年付将近 300 美元买的 YouTube 研究工具越来越复杂，他用 Claude 五分钟就把自己真正需要的核心功能做出来了。这不是 demo，是真的把订阅换成自己造的小工具。我会顺着看这条线：当写小工具的成本降到几分钟，一批功能大而全、但核心价值很窄的 SaaS 会先被用户自己在本地替掉。真正留下来的，是有数据、有网络效应、或者别人接不进来的那种。

### 1. Sam Altman 说 dot 是他最喜欢的 OpenAI 产品，因为它每天都在学他的工作流

[查看原文](https://x.com/sama/status/2106085986606403684) · 来源：Sam Altman (@sama)

Sam Altman 公开说 dot 是目前他最喜欢的 OpenAI 产品，理由不是 benchmark，而是它每天都在变好，越来越懂他的工作方式和风格，还能替他处理那些他讨厌、会不断堆积成心理负担的事情。这条信息量在机制：dot 的价值来自持续积累的个人上下文，而不是一次性的强模型输出。我的判断是，真正跑出来的消费级 agent 会越来越不像聊天框，更像一个长期开着、替你消化杂事的伴随层。对做产品的人来说，值得想的是你的 agent 有没有在跨会话记住用户，还是每次都从零开始。

### 2. Garry Tan 谈 GBrain：要的是像 web 一样原生的个人 agent，不是聊天机器人功能

[查看原文](https://x.com/garrytan/status/2106063850453991758) · 来源：Garry Tan (@garrytan)

Garry Tan 描述 GBrain 的目标：让 agent 变得像当年的 web 一样原生、有表现力、理所当然，不是一个聊天机器人里的功能，而是一个懂你、24 小时在线、永远在提前思考、持续改进的个人助手。这条和今天 Altman 谈 dot 的判断高度重合，但 Garry 更强调形态问题——agent 应该是独立的常驻层，而不是被塞进对话窗口。我的判断是，接下来一年真正的分野不在模型能力，而在谁先把这种常驻、有记忆、能主动推进的界面做顺。做 agent 的人应该先把 always-on 和 memory 这两件事做扎实，再谈能力扩展。

### 3. Capy 出现跨 session 协调：一个协作者发起的修改会自动避开你其他线程里的工作

[查看原文](https://x.com/garrytan/status/2106092289173213444) · 来源：Garry Tan (@garrytan)

Garry Tan 提到 Capy 上一个他没想到的跨 session 协调行为：他的协作者 Sina 发起一轮修复，会主动绕开他已经在多个 Capy 线程里推进的工作，而且跟具体模型无关。这说明多个 agent 开始在共享同一份工作状态，而不只是各自跑各自的。我的判断是，这一步比单 agent 跑得久重要得多——一旦并发 agent 要协调，任务分配、冲突回避、状态同步就会变成实打实的 infra 问题，而现在这块还在很早期。做 coding agent 或多 agent 编排的人，值得把跨会话的状态视图当成一等公民来设计。

### 4. Peter Yang 用 Claude 五分钟复刻了自己付费工具的核心里功能

[查看原文](https://x.com/petergyang/status/2106072698564874410) · 来源：Peter Yang (@petergyang)

Peter Yang 说他原本每年花将近 300 美元订阅一个 YouTube 研究工具，但产品越做越复杂。他干脆让 Claude 把核心功能做出来，五分钟搞定。这不是演示，是真实的付费替代行为。我的判断是，当写小工具的成本压到几分钟，第一批被吃掉的会是那些功能堆得很满、但用户真正需要的只有一小块的 SaaS。真正难被替代的是有数据壁垒、网络效应或者别人接不进来的产品。做工具的人该想清楚自己卖的是那层复杂功能，还是那个别人搬不走的核心里。

### 5. 用 Claude Code / Codex 嗅探家庭网络，找出还能接入 agent 的设备

[查看原文](https://x.com/nikunj/status/2106072546206773574) · 来源：Nikunj Kothari (@nikunj)

Nikunj Kothari 分享了一个在家自动化里用 Claude Code 或 Codex 的 prompt：让 agent 嗅探家里网络数据包，结合已有的 Hermes agent（管 Gmail、恒温器、DoorDash、Amazon 等），列出还能接进来的设备，并研究接入方式。这是个很具体的接入工作流，不是聊天演示。我的判断是，agent 真正的价值会先在个人自动化这种乱、碎、接口不统一的场景里暴露出来，因为这里恰好是人类懒得手动排查、而 agent 能一次扫完的地方。对做 agent 工具的人，这类真实家庭网络场景比办公 demo 更能测出你的工具缺什么。

### 6. Claude Code 的 mods 让 You should know 这类扩展真正可用

[查看原文](https://x.com/trq212/status/2106119299484221762) · 来源：Thariq (@trq212)

Thariq 提到 You should know 是跟进 Claude 能力边界的好方式，也是 mods 能做什么的好例子，结论是你可以真正把 Claude Code 改成自己的。这条的价值在于它说的不是模型能力，而是扩展机制怎么让工具贴合个人工作流。我的判断是，coding agent 的竞争正在从模型强不强，转向工具能不能被用户改。谁的扩展点更干净、更容易被社区复用，谁就更可能长出自己的生态。做开发者工具的人应该把可扩展性当成产品的一等功能，而不是加分项。

### 7. 未来模型会更擅长删代码和简化，正好赶上我们代码越堆越多的时候

[查看原文](https://x.com/thsottiaux/status/2106252868307271752) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 说未来的模型会在删代码和简化上强很多，并且来得很及时。这条虽然短，但指了一个现在被低估的方向：agent 帮人加功能的讨论很多，帮人减代码的很少。我的判断是，当 agent 让写代码变便宜，代码库膨胀会变成新的主要成本，能安全地删和重构的能力价值会被重新定价。对做 coding tool 的人，评估指标里应该早点加上删减和简化的质量，而不只是生成量。

### 8. Claude 面向小企业推出新工作流、集成和培训计划

[查看原文](https://claude.com/blog/claude-for-small-business-launches-new-workflows-integrations-and-training-programs) · 来源：Claude Blog

Claude 官方发布面向小企业的工作流、集成和培训计划。这条是产品线动作，没有附带技术细节或使用者复盘，所以信息密度有限。我的判断是，大模型厂商往中小企业走，说明单纯卖 API 或聊天入口的增量在放缓，下一步拼的是能不能把现成的业务工作流打包进去。对做垂直工具的人来说，这意味着通用层会越来越往你的场景里挤，护城河要建在数据和具体行业的接缝上，而不是模型调用的那层壳。
