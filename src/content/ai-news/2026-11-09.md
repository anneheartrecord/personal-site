## 今日判断

今天这批动态里，我更关注 agent 进生产的具体阻力，而不是模型能力。Levie 指出的位置最有用：权限边界、跨系统状态同步、出错后能否回滚。这三件事决定 agent 能不能交给不盯屏的人使用；B 端演示容易，补责任链难，卡点常在 IT 和法务，不在效果。
Karpathy 把 coding agent 拉回验证闭环，我认同这个排序。生成已经够用，缺的是让 agent 自己判断这一步是否做对。工程上要看测试能否自动跑起来、失败信息是否结构化、上下文是否为重试留余量。我看 coding tool 也先看它怎么处理失败，而不是一次能写多少行代码。
给一线 builder 的判断：接下来几个月的差别不在模型选型，而在你把 agent 当功能还是当服务。当服务就要核算单位任务成本、建权限模型、做回滚、交付可验证产出；这些做完，换模型不慌，没做完，模型再强也只是 demo 更亮。

### 1. No Priors 谈 Agent 进生产：成本结构和企业采购在改产品形态

[查看原文](https://www.youtube.com/@NoPriorsPodcast) · 来源：No Priors

这期 No Priors 谈 agent 从演示走向生产：模型能力不再是唯一变量，推理成本、记忆与工具调用的分层、企业采购和合规流程都在反向决定产品形态。最有信息量的是成本拆解，同一工作流里 token 花在规划、检索还是重试，直接决定能否规模化收费。我的判断是，B 端 agent 团队先跑清单位任务成本，再谈能力上限，否则 demo 越惊艳，账单越难看。

<a id="20261109-02"></a>

### 2. Levie：Agent 落地的瓶颈已经从模型转到流程和权限

[查看原文](https://x.com/levie/status/2119111328099168409) · 来源：Aaron Levie (@levie)

Levie 讲企业里 agent 真正卡住的地方：权限边界、系统间状态同步、出错后能否回滚。他把 agent 描述成要嵌进现有审批和责任链的执行者，不是聊天窗口。很多 agent 产品在公司内部推不动，卡在 IT 和法务而不是效果。我的判断是，接下来一年 agent 的差异化会集中在权限模型、审计日志和可回滚的执行设计上，这些是工程活，不是 prompt 活，也很难靠换模型补上。

<a id="20261109-03"></a>

### 3. Karpathy 谈 coding agent：验证闭环比生成能力更稀缺

[查看原文](https://x.com/karpathy/status/2119114537442189652) · 来源：Andrej Karpathy (@karpathy)

Karpathy 把 coding agent 拉回具体问题：模型写代码越来越顺，但决定 agent 能否自己往下走的是可靠验证信号，包括测试、类型检查、能自动跑起来的复现步骤。他讲的是 agent 循环怎么闭合，不是单次补全多强。对做 coding tool 的人是明确提醒：投入应放在可执行验证环境，而不是继续堆上下文长度。我的判断是，谁先把验证环境做成产品的一部分，谁的 agent 才敢放手跑。

<a id="20261109-04"></a>

### 4. Nikunj：Agent 产品的定价还没找到稳定形状

[查看原文](https://x.com/nikunj/status/2119162212044742938) · 来源：Nikunj Kothari (@nikunj)

Nikunj 讨论 agent 商业化的具体摩擦：按 token 计价和按任务结果计价之间没有共识，客户买结果，供应商卖算力，中间的重试和失败成本没人愿意承担。他提到销售侧已经用每完成一个任务多少钱去谈，但后端账仍按调用量走。定价形状会直接决定架构选择，要不要为省钱砍掉重试次数就是例子。我的判断是，明年会有一批产品把定价绑到可验证产出上，这比一次模型升级更能改变竞争格局。

<a id="20261109-05"></a>

### 5. Aditya Agarwal：模型能力之外，产品侧吸收速度是约束

[查看原文](https://x.com/adityaag/status/2119157297167372646) · 来源：Aditya Agarwal (@adityaag)

Aditya 关注模型能力曲线和产品侧吸收速度的落差：新能力出来后，团队真正的瓶颈是能否接进已有流程、有没有人负责验证输出、旧工作流要不要改。他给的方向偏组织侧，不是模型评测。如果吸收速度是约束，团队该优化接入路径和验证环节，不是继续追榜。我的判断是，中小团队现在多囤接入能力，比追每一版新模型更划算，能力溢出已经发生，接不住的部分才是真损失。

<a id="20261109-06"></a>

### 6. Swyx：企业内 agent 扩散的阻力在接入复制

[查看原文](https://x.com/swyx/status/2119210582654210255) · 来源：Swyx (@swyx)

Swyx 讲企业内 agent 扩散的实际阻力，偏组织侧：一个 agent 在一个团队跑通，换到隔壁团队往往要重来，因为数据权限、术语习惯和流程都不一样。这类阻力不技术，但直接决定 agent 产品做平台还是项目制交付。我的判断是，能被复制的不是 prompt，而是接入方式；谁把接入做成模板、权限配置和可回放运行记录，谁才谈得上规模化，否则每一单都是咨询生意。
