## 今日判断

今天最值得记的一件事是 Agent Skills 被捐给 Agentic AI Foundation，和 MCP 放在一起。Boris 说它原本只是 Claude Code 里的一个实验，后来行业里一堆人跟着用，Anthropic 觉得与其自己拿着，不如交出去。这个动作比多数模型发布更有分量：skill 的目录结构、加载方式、权限边界，如果只有一家定义，大家就是被迫兼容；进了基金会，至少有机会变成跨产品的事实标准。我在看的是它能不能被别的 runtime 真正实现，而不只是被引用。

另一条线索是安全开始在 agent 产品里变成默认配置。Claude 下周起在 Pro/Max/Team 默认开 auto mode，不再每一步都问人，改成一个自动检查去拦高风险动作，用户还能切回手动。同时 Rauch 那几条在喊杀掉静态凭证、改 OIDC，Levie 说 security through obscurity 在自主系统面前彻底结束。这几个说法指向同一个机制：agent 会穷举攻击面，人肉审批既拖慢工作流又给不了真保证，所以权限得从凭证层面收紧，而不是靠弹窗。

工程侧我还注意 Swyx 那句 Opus 5.5 是最好的工时估算模型。这话听着像夸模型，实际是在说 delegation 的接口问题：我们让 agent 干活时，它报 2-3 天是按人的节奏报，真实可能是 2-3 小时，这个偏差会直接搞坏排期和并行调度。谁先把 agent 的 ETA 校准做成产品能力，谁的工作流就更可信。今天我倾向认为，skills 标准化、权限收口、工时校准这三件事，比又一个 benchmark 更影响 builder 接下来怎么建东西。

### 2. Claude 客户端默认切到 auto mode，用自动检查替代逐步审批

[查看原文](https://x.com/claudeai/status/2113360845409583307) · 来源：Claude (@claudeai)

Claude 宣布从下周开始，web、桌面、移动端的会话在 Pro、Max、Team 套餐上默认走 auto mode，不再每步请用户批准，而是由一个自动检查拦截高风险动作，用户可随时切回手动。这等于官方承认逐步审批在实际使用中太慢，把安全责任挪到策略层。我的判断是：这是 agent 产品从演示走向日常使用的必经一步，但默认开 auto 意味着失败成本从点错按钮变成整段流程跑偏，团队需要提前想清楚哪些动作必须留人工闸门。

### 5. Swyx：Opus 5.5 是最好的工时估算模型，agent 报时应该按 agent 的节奏

[查看原文](https://x.com/swyx/status/2113283272130412684) · 来源：Swyx (@swyx)

Swyx 说 Opus 5.5 是他用过最好的工时估算模型，并指出一个正在变重要的问题：当我们把工作委托给 agent，它不该按人类节奏报 2-3 个工作日，而对一个可并行的 agent 来说实际是 2-3 小时。我的判断是：这不是模型彩蛋，而是 delegation 的接口缺陷。排期、并行调度、成本预估都依赖 ETA，如果模型默认按人报时，整个计划层都会失真；把 agent 的估算校准成产品能力，是接下来工作流工具的一个差异点。

<a id="20261024-06"></a>

### 6. Rauch：该杀掉静态凭证，用 OIDC 做数据与 token 的自毁密钥

[查看原文](https://x.com/rauchg/status/2113399539227136084) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 说该淘汰静态凭证了，攻击和泄露总会发生，但如果攻击者只能偷到会自毁的密钥，风险面会小很多。他把这比作当年全行业一起推 TLS 绿锁，主张对 OIDC 做同样的事。我的判断是：agent 会长期持有访问 token 并高频调用外部系统，静态密钥的生命周期管理在大规模自动化下基本不可维护，把短期凭证做成默认不是可选优化，而是 agent 上生产的前置条件。

### 7. Levie：security through obscurity 在自主系统面前结束

[查看原文](https://x.com/levie/status/2113499900399034689) · 来源：Aaron Levie (@levie)

Aaron Levie 认为任何形式的安全靠隐蔽都彻底结束了，因为自主系统会翻遍每个缝隙、试遍每种攻击排列组合。他推论大量遗留企业基础设施要升级，安全实践要现代化，数据管线和访问控制要重做，agent 在防守侧能加速这些工作也能模拟风险。我的判断是：这条的价值在于它解释了为什么企业 agent 落地慢，瓶颈不在模型能力，而在老系统的清理成本，这也意味着做 agent 安全工具和审计的团队有真实需求。

### 8. Aside Browser：让 agent 真正会用网页的浏览器方案

[查看原文](https://x.com/garrytan/status/2113367007567794563) · 来源：Garry Tan (@garrytan)

Garry Tan 推荐 Aside Browser，称它是让 agent 真正擅长使用网页的一个实在方案。信息很简短，但指向一个具体问题：agent 操作网页时往往卡在渲染、登录态、动态内容和反爬上，通用浏览器并不是为 agent 设计的。我的判断是：agent 专用浏览器正在成为独立品类，谁把会话、权限、可观测性做对，谁就能吃到大量 agent 任务的入口，但这条只有一句推荐，还需要看产品和源码细节才能给更高分。
