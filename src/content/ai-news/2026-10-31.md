## 今日判断

今天我把大部分注意力放在 coding agent 这条线上。Thibault 关于编码侧更新的帖子拿到三万五千多赞、六千多条回复，说明大量开发者当天就在自己仓库里跑了一遍。我看下来，这次值得记的不是跑分，而是长任务里工具调用的稳定性：一个 agent 连续改十几个文件、中间报错还能自己回滚重试。决定它能不能进生产的是这个，不是单次补全的准确率。

另一条线是 agent 往企业工作流里钻。Aaron Levie 和 Guillermo Rauch 说的其实是同一件事的两面：模型能力已经够用，卡住的是权限、审计和可回滚的部署方式。Rauch 把 agent 当成一个需要观测、需要灰度的服务来对待，这个视角对做 infra 的人比多几千 token 上下文有用得多。Google Labs 也是这个方向，把 agent 塞进现成的工作入口，而不是再开一个聊天框。

MAD Podcast 这期我听了大半，嘉宾讲 agent 的运行时成本和状态管理，讲得实在。我的判断是，接下来两个月，builder 之间的差距不在会不会调模型，而在有没有一套让 agent 失败得起、重试得起、并且能被人审的工作流。先把这个做出来的人，才敢把 agent 放到真实用户面前。

### 2. MAD Podcast：agent 运行时成本和状态管理被摆上台面

[查看原文](https://www.youtube.com/@DataDrivenNYC/videos) · 来源：The MAD Podcast with Matt Turck

The MAD Podcast 今天更新一期，Matt Turck 和几位做 agent infra 的人聊运行时与成本，他同时在 X 上发了同一条内容，建议直接听原始音频。大部分 agent 讨论还停在能力演示，真正决定能否上生产的是跑一次多少钱、失败怎么恢复、状态存在哪里。这类长内容对做 infra 的人价值高于模型发布，尤其并发和成本归因的部分。建议一边听一边对着自己系统的 trace 核对哪里对不上。

### 3. Thariq 讲人和 coding agent 的分工边界

[查看原文](https://x.com/trq212/status/2115937378674372783) · 来源：Thariq (@trq212)

Thariq 发了一条关于 coding agent 工作流的帖子，拿到九千五百多赞。内容不是模型本身，而是人和 agent 怎么分工：哪些步骤交出去，哪些必须人来确认。这是多数团队上手 agent 后第一个卡住的地方，任务整个丢出去，返工比自己做还慢，最后得出 agent 不好用的结论。他这类一线使用者划出的边界比任何 benchmark 都更容易直接迁移，建议对着自己团队的日常任务列一遍，标出哪些环节早该交出去。

### 4. Levie：企业卡住 agent 的不是模型，是审计和回滚

[查看原文](https://x.com/levie/status/2116029912243184006) · 来源：Aaron Levie (@levie)

Aaron Levie 谈企业里 agent 落地的实际障碍，一千多赞、一百多条回复，观点集中在权限、合规和可审计，而不是模型能力。企业客户不是不想用 agent，是不能接受一个改错了却查不出原因的系统，这决定产品先做能力还是先做治理。做 B 端 agent 的团队应该把审计日志和回滚能力列为一级功能排期，不要等上线后补，这决定能不能过采购那一关，优先级高于模型选型。

<a id="20261031-05"></a>

### 5. Rauch：把 agent 当成一个会挂掉的服务来部署

[查看原文](https://x.com/rauchg/status/2115874115118834153) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 从部署角度谈 agent，延续 Vercel 一直推的思路，把 agent 当成一个需要观测、需要灰度、随时可能挂掉的服务，而不是一个更聪明的函数。这个视角决定团队怎么搭工具链：有没有 trace、有没有回放、能不能把一次失败的 agent run 完整复现。检查方法很直接，先问自己能不能复现过去 24 小时里任意一次失败，答不上来就先别扩规模，扩了只是把不可观测的失败放大。

### 6. Google Labs 把 agent 塞进已有入口，而不是再开一个聊天框

[查看原文](https://x.com/GoogleLabs/status/2115884247504625669) · 来源：Google Labs (@GoogleLabs)

Google Labs 放出新的 agent 方向产品更新，位置在现有工作流入口和基础设施之间。Google 一贯把 agent 嵌进用户已经在用的界面，而不是让用户再学一个新东西，对产品团队的启发是分发优先级高于功能堆叠。值得盯的是权限模型和上下文来源：如果还要用户手动投喂资料，它跟现有自动化工具差别不大；能接上 Workspace 既有数据，才算产品层面的变化。

[查看原文](https://x.com/garrytan/status/2115922231910084638) · 来源：Garry Tan (@garrytan)

### 8. Google 模型侧更新：上下文和多模态又往前推了一格

[查看原文](https://x.com/joshwoodward/status/2115953461108023400) · 来源：Josh Woodward (@joshwoodward)

Josh Woodward 发 Google 模型侧的一条更新，一千一百多赞。Google 这边的节奏是把模型能力先接到消费级产品上，版本更新对开发者更多是间接影响，但会慢慢改变大家对上下文长度和多模态输入的默认假设。不在 Google 生态里的，看结论就够了：上下文窗口又一次被推前，一些为省 token 而做的分块和检索设计可以重新评估。别为了等一个版本重构，但至少把假设记下来。
