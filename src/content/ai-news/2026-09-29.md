## 今日判断

我今天更关注 Rauch 那条.他把 Mini 浏览器从 Electron + Bun 迁到 Rust/Swift,用 cef crate 打包 Chromium,fx acp 嵌 agent,再通过 local fx CLI 用 MCP 管浏览器.这不是换语言炫技,是 agent 时代的客户端架构在往 native 收,因为细粒度 focus 和输入控制在 JS 里是噩梦,在 native 里纯是小事.我判断接下来一年,桌面端和云端都会有一批服务重新长出 native 壳,Electron 只在快速验证期还有优势.\n\n第二条我留在心里的,是 Steinberger 说的 let codex decide which tests need to run. 这话听起来像偷懒,但它背后是 CI 策略变化:测试集不再全量跑,由模型按 diff 和风险挑要跑的用例,再配 hourly 定时兜底.如果测试选择器本身能被评测和回归,这会直接改掉大团队的 merge gate 设计;改不好,就是另一种把 bug 藏得更深的方式.\n\nLevie 关于 agent 降低转换摩擦的推,和 Shipper 那句 humans adopt rational agents,其实在讲同一件事:agent 一旦替用户做高效选择,过去靠惯性收费的生意会先被冲击,医疗、旅行、本地服务这类本来太麻烦的市场反而会被解锁.我的判断是,做企业软件的人现在就该拿自己产品的 switching cost 过一遍,哪些 friction 是用户真需要的,哪些只是你一直在收的租金.

### 1. Rauch 把 Mini 浏览器从 Electron 迁到 Rust/Swift,agent 通过 MCP 接管浏览器

[查看原文](https://x.com/rauchg/status/2104428800134013205) · 来源：Guillermo Rauch (@rauchg)

Rauch 把 Mini 浏览器从 Electron + Bun 迁到 Rust 和 Swift,用 cef crate 直接打包最新 Chromium,fx acp 把 agent 嵌进 app,fx 再通过本地 CLI 以 MCP server 的方式管理浏览器。结果不只是更快更安全,迭代体验也比 JS 栈好,细粒度 focus 和输入控制这些在 JS 里很难写的东西在 native 里直接工作。他还借 DHH 在 Rails World 的说法抛出一个判断:整个软件世界会加速 nativify,Vercel 押 Fluid 就是为了支持 Rust、Go、Zig、scriptc 这些路径。我看这条的价值不在 Rust 本身,而在于它给了一个 agent 接管本地软件的完整接线方式:agent 不直接碰 UI,而是通过 ACP 和 MCP 暴露的能力去操作浏览器。

### 2. Steinberger 想让 codex 决定哪些测试该跑,CI 从全量改成按需加小时级

[查看原文](https://x.com/steipete/status/2104305554760114488) · 来源：Peter Steinberger (@steipete)

Steinberger 说 Blacksmith 作为赞助方已经撑不住负载,所以计划让 codex 决定哪些测试真的需要跑,大幅裁剪 CI,再配每小时定时跑测试兜底。这和他日常用 coding agent 的工作流直接相关:当 agent 一天能产出大量 diff,全量跑测试的成本会先爆掉,测试选择本身就成了要设计的一环。我判断这条路能不能走通,取决于测试选择器能不能被独立评测:如果漏选率可观测、可回归,那 merge gate 会从全量绿灯变成风险分级;如果不可观测,就是把 bug 藏得更深。对已经在用 CI 的中大型团队,这是接下来半年值得做小范围实验的方向。

### 3. Levie:agent 降低转换摩擦,靠惯性收费的市场先被冲击

[查看原文](https://x.com/levie/status/2104350592290406849) · 来源：Aaron Levie (@levie)

Levie 把 agent 替用户做最优选择后的经济影响分成两块:一部分市场过去靠用户换习惯的高摩擦收租,agent 会让切换成本下降、竞争急剧加剧;另一部分市场本来被摩擦压住,比如医疗、旅行、本地服务、部分信息服务,agent 反而会解锁新的交易。他没有停在宏观,而是点出两类市场的不同机制。我的判断是,做企业软件的人现在应该拿自己产品的 switching cost 过一遍:哪些 friction 是用户真正需要保留的,哪些只是你一直在收的租金。

### 4. Shipper:建模理性人的行业,在人类用上理性 agent 后慌了

[查看原文](https://x.com/danshipper/status/2104302924251951553) · 来源：Dan Shipper (@danshipper)

Shipper 这句很短:industry built on modeling humans as rational agents panics as humans adopt rational agents。意思是过去一大堆行业靠假设人是理性行动者来建模、定价、做推荐,现在人真的把理性决策外包给 agent,原有的前提就松了。这条本身没有新事实,但它和 Levie 那条互为印证:agent 不是替人点按钮,而是替人做选择,一旦选择权转移,依赖用户惯性、信息差、注意力的生意模式都要重估。我看下来,这是做 agent 产品的人在写 pitch 和设计指标时值得反复想的一句话。
