今天最值得关注的是 Vercel AI Gateway 的那组模型支出数据。Anthropic 在两个月内从 69% 掉到 40%，OpenAI 从 10% 涨到 24%，Kimi K3 和 DeepSeek 拿走了 Anthropic 一半的流失份额。我在一线听到的情况也是这样：没有人再只押一家模型了，网关、路由、fallback 正在变成标配，模型层的忠诚度基本消失。真正在建设的人应该反过来看这件事，如果你的产品还绑死在单一模型上，议价和切换成本都会落在你身上。

### 1. Vercel AI Gateway 数据：模型支出正在快速去中心化

[查看原文](https://x.com/rauchg/status/2103216656747262419) · 来源：Guillermo Rauch (@rauchg)

Vercel CEO Guillermo Rauch 公开了 Vercel AI Gateway 最近两个月的模型支出分布：Anthropic 仍是第一，但从 69% 降到 40%；OpenAI 从 10% 涨到 24%（GPT-6 Astra 和 GPT 5.6 Sol 拉动），在 token 数上已经第一；Kimi K3 加 DeepSeek 拿走了 Anthropic 流失份额的大约一半；Opus 5.5 上线两天就占到 10% 支出；图像生成里 OpenAI 占 62%。这是一份真实产品流量侧的账单，而不是厂商口径。我的判断是模型层忠诚度正在消失，网关和路由会变成默认基础设施，Builder 该把多模型切换当成架构前提而不是可选项。

### 2. 给 Agent 一个更激进的目标，而不是让它随便清理

[查看原文](https://x.com/steipete/status/2103148444701610233) · 来源：Peter Steinberger (@steipete)

Peter Steinberger 分享了一个很具体的 agent 使用经验：如果你只告诉 agent 去清理代码，它会过早停止；换成量化的激进目标，比如在保持覆盖率偏差 2% 以内删掉 20% 最没用的测试，agent 的完成度会明显提高。这条没有玄学，就是把验收标准写进 prompt。我的判断是 coding agent 的瓶颈很多时候不在模型能力，而在任务定义。把目标写成带约束和阈值的可验证条件，比任何提示词技巧都稳定，这也是失败复盘里最容易沉淀成工程规范的一类经验。

### 3. Claude Code 把 plan mode 开放成可定制模式

[查看原文](https://x.com/trq212/status/2103212051065921632) · 来源：Thariq (@trq212)

Thariq 在收到大量反馈后给出 plan mode 的处理方案：把它做成内建 mod，允许 mod 添加新模式或覆盖 shift+tab 快捷键。反馈里有两类人，一类自己就会规划不需要 plan mode，另一类偏好进入一个 Claude 只陪你想和头脑风暴的模式。这背后是 agent 产品的一个真实分歧：规划到底是用户的动作还是产品提供的状态。我的判断是把它做成可插拔模式而不是强制流程，方向是对的，因为不同任务的规划密度差很多，把 mode 变成可组合单元比写死一个功能更有长期价值。

### 4. VAST Data 创始人讲 AI 栈里那层没人讲的软件基础设施

[查看原文](https://www.youtube.com/@DataDrivenNYC/videos) · 来源：The MAD Podcast with Matt Turck

Matt Turck 与 VAST Data CEO Renen Hallak 的对谈，聚焦 Jensen 五层蛋糕里被最少理解的那层，软件基础设施。节目里给出了具体机制：白天推理、晚上微调的工作负载节律；一个 AI 云客户从 500PB 需求追加到再加两个 EB；以及 VAST 的 DASE 架构，用 shared everything 去承载万亿级向量，解释为什么老数据库在这类负载下会崩。我的判断是模型和 GPU 信息已经过载，真正的稀缺认知在数据与存储层。做 infra 的人应该顺着白天推理、晚上微调这个节律去反推自己的调度和存储设计。

### 5. Claude Code 允许自定义和分享 plan mode 提示词

[查看原文](https://x.com/trq212/status/2103212052391354794) · 来源：Thariq (@trq212)

Thariq 补充说明 plan mode 改造后会开放的能力：可以自定义 plan mode 的提示词，创建并分享自己的模式，或者干脆忽略它把 shift+tab 绑定到别的地方。这条和主帖是同一事件，但它交代了可扩展点在哪。我的判断是这决定了团队能不能把自己的规范和上下文写进 agent 的规划阶段，而不是每次靠手打 prompt。对已经把 Claude Code 放进团队工作流的 builder 来说，模式可分享意味着规划阶段可以像代码规范一样被版本化。

### 6. 每个小企业最终都会有定制软件，差异化在最后一公里

[查看原文](https://x.com/nikunj/status/2103360292973633770) · 来源：Nikunj Kothari (@nikunj)

Nikunj Kothari 引用一段观点：每个小企业主，尤其我们做的 trades 行业，最终都会有定制软件，而最后一公里正是能提供差异化体验的地方。这个说法对做垂直 agent 的人有参考价值，因为它把定制软件从大企业专属重新定义成小企业默认状态。我的判断是这句话成立的前提是生成成本足够低、领域知识能复用，否则最后一公里依然会变成一个个做不完的项目制外包。值得关注，但目前还停在判断层面，没有可验证的数据。
