## 今日判断

今天我最关注的不是哪一个模型更强，而是 Codex CLI 的使用量在 devday 之后翻了一倍。Thibault 列的更新很枯燥：prompt presets、inline model 和 permission 设置、企业 MCP 登录、长会话恢复修复、Windows 公司代理认证。但这几项恰好都是「把它塞进真实公司工作流」才会痛的地方。CLI 是 coding agent 最贴近终端的形态，它增长 2 倍说明团队真的在把 agent 当日常工具跑，而不是 demo。我判断接下来 coding tool 的竞争点会从模型能力转到这些脏活：权限、代理、会话恢复、企业登录。谁能把 agent 塞进企业网络里还不崩，谁就能拿到持续使用的量。

第二件我更在意的是 Rauch 和 Levie 从两个角度说同一件事。Rauch 讲的是共享 VM 上 agent 之间通过 CPU cache 计时互相探测的 noisy neighbor 攻击，他的结论很诚实：除了独占硬件没有完全解法，Vercel Sandbox 只能堆缓解手段加持续红队。Levie 则说 agent swarm 做安全会是最大品类之一，因为算力投入直接换风险覆盖。这两条合起来看，agent 大规模跑起来之后，安全成本和隔离成本会变成 infra 账单里实打实的一行，不是概念。

还有一条人事：Thariq 离开 Anthropic，之前一年多在做 Claude Code。加上 Amjad 把 Chroma 团队收进 Replit 去做 agent 的 context 和 memory，我看下来信号是一致的：coding agent 和 agent memory 已经进入拼团队和拼工程落地的阶段，而不是拼谁先发一个功能。对一线 builder 来说，值得抄的不是新闻，是这几家公司正在补的那几个具体短板。

### 1. Codex CLI 一周加了企业级脏活，用量翻倍

[查看原文](https://x.com/thsottiaux/status/2113770862860222611) · 来源：Thibault Sottiaux (@thsottiaux)

OpenAI 的 Thibault Sottiaux 公布 Codex CLI 更新：可复用的 prompt presets、行内的模型与权限设置、企业 MCP 登录，修复长会话恢复失败，并补上 Windows 公司代理认证。他同时提到 CLI 自 devday 以来用量增长 2 倍。这些功能单看都不性感，但每一条都对应企业环境里的真实摩擦：代理认证不过、长会话断掉、MCP 没法统一登录。我的判断是 coding agent 的胜负正在从模型跑分转到这些接入层细节，能进公司网络还不崩的工具才会被天天用。

### 2. Codex 改推理设置不再清空缓存

[查看原文](https://x.com/thsottiaux/status/2113770573994299544) · 来源：Thibault Sottiaux (@thsottiaux)

同一天 Thibault 还提到一个小但实用的改动：在对话中途切换 Codex 的推理设置，不再让缓存失效。这听起来像底层细节，但实际用起来差别很大——经常有人一边跑任务一边调 reasoning 强度，过去一改就把上下文缓存打掉，延迟和成本都上来了。我的判断是这类改动才是 agent 工具从能用走向顺手的分水岭，一个每天跑几十次会话的人对缓存命中的体感远比对模型版本敏感。

### 3. 共享 VM 上的 agent 计时攻击：除了独占硬件没有完整解

[查看原文](https://x.com/rauchg/status/2113759533801877920) · 来源：Guillermo Rauch (@rauchg)

Rauch 解释了 OpenAI 发现的一类 agent 攻击：两个 agent 跑在同一台共享 VM 上，一个通过制造 CPU cache 噪音，另一个靠给自己的计算计时就能探测到对方，他称之为 noisy neighbor 攻击。他指出这类计时攻击从 2015 年就已知，且没有完整解法，唯一彻底方案是每个 agent 独占硬件，但经济上代价很大。Vercel Sandbox 的做法是部署所有可行的缓解手段，再加持续监控和红队测试。我的判断是 agent 规模化之后隔离成本会写进 infra 账单。

<a id="20261025-04"></a>

### 4. Levie：agent swarm 做安全会是最大品类之一

[查看原文](https://x.com/levie/status/2113738768645808277) · 来源：Aaron Levie (@levie)

Levie 判断用于网络防御的 agent swarm 将成为 AI 最大的品类之一：agent 审查代码和基础设施、遍历各种风险组合、处理海量数据，很多以前没人来得及做的测试，agent 可以大规模铺开。他的核心论点是安全天然是算力投入等于价值产出的领域，适合 swarm 这种并行结构。我的判断是这条要和 Rauch 那篇一起看：需求侧确实存在，但供给侧的隔离与安全成本会决定这个品类能有多少毛利。

### 7. Cloudflare CTO：AI 既是安全灾难也是解法，但边界怎么划

[查看原文](https://www.youtube.com/@NoPriorsPodcast) · 来源：No Priors

No Priors 这期请到 Cloudflare CTO Dane Knecht，主题是为 agentic web 普及安全能力。开场就抛出一个尖锐问题：AI 既是制造安全灾难的工具，也可能是更快解决它的工具，甚至有人认真讨论过要不要把关键设施 air gap。Knecht 说过去一年像压缩了十年。我的判断是边缘与安全基础设施厂商正在被 agent 流量推着重构策略，这对任何要把 agent 部署到公网的人都是必须跟进的变量。

### 8. Claude Duet 公布安全、隐私与安全性的细节

[查看原文](https://x.com/claudeai/status/2113736176737845353) · 来源：Claude (@claudeai)

Claude 官方账号放出 Claude Duet 在安全、隐私、安全性方面的更深入说明。这条本身是官方宣传口径，信息密度不高，但放到今天多条关于 agent 攻击面和隔离成本的内容里看，它提供了一个对照：模型厂商开始在发布时就讲清边界与防护设计，而不是事后补。我的判断是这类说明值得产品负责人扫一眼，用来校准自己对多 agent 交互风险的预期，但不要当成技术细节来读。
