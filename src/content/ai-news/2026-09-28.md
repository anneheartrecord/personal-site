### 1. Garry Tan：修生产 bug 已经默认走 agent 规划

[查看原文](https://x.com/garrytan/status/2103989902476259702) · 来源：Garry Tan (@garrytan)

Garry Tan 说他现在最喜欢的修 bug 方式是 @capydotai 的 GStack /autoplan，直接跑在生产 issue 上，模型用 GPT-6 中等推理档。这条信息量不在工具本身，而在于它描述的是一个已经稳定使用的工作流：把生产环境的问题交给 agent 先做规划和定位，人再做判断。对一个每天要处理线上故障的团队来说，这意味着 coding agent 的定位正在从补全代码转向接手诊断和方案生成。我的判断是，接下来一年真正的分水岭不是 agent 会不会写，而是团队有没有把验证环节做成可复用的流程，否则 agent 只是把 review 压力放大。

### 2. Claude Code 做视频一年后：迭代成本降了多少

[查看原文](https://x.com/trq212/status/2103897226154328502) · 来源：Thariq (@trq212)

Thariq 回顾了一年前用 Claude Code 生成视频的经历，当时每个片段都要反复迭代、指出错误细节才能做对。现在他感叹进展太快。这条值得看的原因不是怀旧，而是它给出了一个具体的对照：同样一类任务，过去需要多轮人工纠错，现在迭代成本大幅下降。对做内容工具或 agent 产品的人来说，这种体感变化意味着 prompt 容错窗口在变宽，产品设计里那些为「模型不可靠」准备的兜底交互，可能正在变成负担。我的判断是，凡是围绕「帮用户纠正 AI 输出」设计的功能，都值得重新问一遍现在还值不值得做。

### 3. Guillermo Rauch：AI 生成的 PR 说明正在让人放弃阅读

[查看原文](https://x.com/rauchg/status/2103939888513274147) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 提出一个很具体的担忧：AI 生成的代码、PR 说明和文档大量涌入后，阅读这件事本身正在被贬值。他举了一个正在传播的例子，一个被归功于编译器改动的性能提升 PR，说明文字里 AI 自己都说功劳其实来自算法和数据结构的改动。这意味着 AI 生成的低质量、未经验证的叙述正在消耗 reviewer 的注意力。对一线团队来说，这不是抽象的文化问题，而是 review 流程要不要强制要求提供可验证证据的问题。我的判断是，接下来工程规范里会多出一条：AI 生成的说明必须附上可复现的依据，否则默认不采信。

### 4. Claude 用量限制从勉强可用变成基本无限

[查看原文](https://x.com/petergyang/status/2104066667361992892) · 来源：Peter Yang (@petergyang)

Peter Yang 观察到 Claude 的限制从「勉强可用」变成「基本无限」。这条本身信息很少，但对做 agent 产品的人是一个实际信号：当底层模型的调用额度不再是最紧的约束，产品设计里那些为省 token 做的降级、缓存、截断策略就可以重新评估。反过来，如果额度宽松是暂时的，把它当长期假设写进架构就有风险。我的判断是，平台配额的变化会直接影响 agent 产品的单位经济模型，做 infra 的人应该把额度波动当成一个需要监控的外部依赖，而不是当成默认稳定的资源。

### 5. 用 Gemini 音频 API 搭一个日语对话练习产品

[查看原文](https://x.com/petergyang/status/2104059554204188833) · 来源：Peter Yang (@petergyang)

Peter Yang 在做一个用 Gemini 音频 API 教人日语对话的应用，结构是 10 课，每课 10 个短语。这条的价值在于它给出了音频模型一个具体、小而完整的产品形态，不是 demo。对做教育或语言工具的 builder 来说，这个拆法值得参考：用固定课数控制生成范围，用固定短语数控制每次交互负担。我的判断是，音频 API 的真正增量不在语音合成质量，而在于能不能撑起连续的、有记忆的对话循环，这决定了它能不能从练习工具变成真正的学习产品。

### 6. Inception 创始人谈扩散模型为什么会在推理上胜出

[查看原文](https://www.youtube.com/@NoPriorsPodcast) · 来源：No Priors

No Priors 这一期请到 Inception 联合创始人、扩散模型奠基人之一 Stefano Ermon，主题是为什么扩散模型会在 AI 推理上胜出。他讲了自己从 2014 年在斯坦福做生成模型、当时只能生成 MNIST 灰度数字、发论文都困难，到现在把速度和效率作为挑战大实验室的核心。这条更偏长期判断，但对做推理 infra 的人有实际意义：如果扩散路线在效率上成立，模型服务层的架构假设会跟着变。我的判断是，推理效率会是接下来几年最实际的竞争维度，做 SDK 和模型平台的人都该把这条放进自己的技术雷达。
