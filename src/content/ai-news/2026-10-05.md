## 今日判断

我今天更关注一件事：AI agent 的真实使用正在从“问答”变成“替我跑完一件事”。Thibault 那条让助手清空收件箱的记录看下来很普通，但细节是关键——它不是简单分类，而是先批量验证哪些邮件能删、给工作中的邮件打标签、再把需要回复的邮件带着背景上下文推到他面前。这套流程正好对应 Aaron Levie 说的 bimodal 状态：coding 已经跑通，其他知识工作卡在“工作流没为 agent 重设计”。

把这两条与 Madhu Guru 那条放在一起看，产品问题就清楚了。现在大多数 AI 产品是有一百个拉杆的驾驶舱，模型选择、连接器、权限、token 用量全扔给用户；能跑通收件箱的 agent 反而不让你选模型。我判断接下来 12 个月真正的分化不在模型能力，而在谁敢把复杂度藏起来，围绕一个具体工作流做默认路径。Ryo Lu 说的 convergence to the mean 是个反方向警钟：工具越好用，大家越容易做出同一套东西。Infra 侧 VAST Data 的访谈也值得记一笔，客户从 500PB 临时加到 2.5EB，说明数据层压力是真实订单驱动的，不是叙事。

### 1. Aaron Levie：Agent 落地严重两极分化，卡点在工作流重设计

[查看原文](https://x.com/levie/status/2106583814709633413) · 来源：Aaron Levie (@levie)

Aaron Levie 说 AI agent 的采用现在是明显两极分化：coding 以及 coding 相邻的任务已经起飞，其余知识工作仍处极早期。即使在 coding 内部，也分化为少数开发者在跑后台并行 agent、多数人仍是一对一使用。他认为卡点不是模型，而是绝大多数工作流需要为 agent 重新设计——数据要以新方式接线，决策的问责与责任归属要重新定义，治理、合规、安全都要升级。这条的价值在于把“agent 落地难”从模型能力问题拉回到产品与流程工程问题，对正在做企业 agent 的人是一个明确的优先级提示：先改工作流，再谈模型。

### 2. OpenAI 开发者用 agent 清空收件箱：批量验证删除、自动打标签、带上下文起草回复

[查看原文](https://x.com/thsottiaux/status/2106603980386394123) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 记录了他让 agent 处理邮箱的完整过程：批量验证并删除不需要保留的邮件类别、识别他工作相关邮件类型并自动打标签、把需要回复的邮件逐一列出，同时在后台搜索相关上下文帮助回复准确。他提到借此处理了大量直接通过邮件发给他的反馈与请求。这不是一个演示，而是一线 builder 用 agent 跑完真实工作流的记录。价值在于展示了 agent 从“能回答”走向“替我执行并保持判断”的路径：批量验证、分类、上下文检索、人工确认四个环节都保留了 human in the loop。对做 agent 产品的人来说，这是一份可直接拆解的任务分解样本。

### 3. Madhu Guru：AI 采用率低是产品问题，别把用户扔进百个拉杆的驾驶舱

[查看原文](https://x.com/realmadhuguru/status/2106450089938157720) · 来源：Madhu Guru (@realmadhuguru)

Madhu Guru 说今天 AI 采用本质上是个产品问题：即使在付费用户里，使用深度也很浅。原因是大多数 AI 产品长得像有一百个拉杆的飞机驾驶舱——连接器、权限、模型选择、token 用量统统暴露给用户。他认为这已经开始改变，未来 12 个月会明显不同，因为产品团队开始成熟，会把 AI 产品做得更易用。这条和 Levie 的判断可以互相印证：模型能力不再是瓶颈，把复杂度藏起来、围绕具体任务给默认路径才是。对一线 builder 来说，这意味着产品判断力会比接模型能力更值钱。

### 4. VAST Data 创始人：AI 云客户从 500PB 临时追加到 2.5EB，数据层压力是真实订单

[查看原文](https://www.youtube.com/watch?v=awoR908Yu5Y) · 来源：The MAD Podcast with Matt Turck

Matt Turck 采访 VAST Data 创始人 Renen Hallak，聚焦 GPU 之下的数据基础设施层。最有信息量的细节是：一个 AI 云客户原计划三年用 500PB，后来回来说还要再加两个 EB。VAST 估值约 300 亿美元，服务 xAI 和多家大型 AI 云。Renen 把这一层定位在 Jensen 五层蛋糕的中间——软件基础设施，下接硬件、上接模型。对做 AI Infra 的人来说，这不是叙事而是订单信号：模型层的扩张正在把数据存储、吞吐、检索这一层推到真实的规模压力下，值得关注谁能在 EB 级别保持性能与成本。

### 5. Ryo Lu：AI 让趋同变得丝滑，产品开始互相抄而不是表达自己

[查看原文](https://x.com/ryolu_/status/2106337039201505453) · 来源：Ryo Lu (@ryolu_)

Ryo Lu 描述了一种趋同现象：当所有人都看别人做什么来决定自己做什么，最终就停止做自己的东西，抄语言、抄审美、抄功能，称之为学习市场或最佳实践，结果一切变得熟悉、抛光、可互换。他的关键论点是 AI 让这个循环变得没有摩擦——它能从比我们视野更多的参考里取样。这条不是反对 AI，而是提醒做产品的人在 agent 和生成能力普及后，差异化来自保留“为什么要做这个”的理由，而不是把反馈当成创作本身。对一线 builder 来说，这是个值得贴在墙上的反向提醒。

### 6. Guillermo Rauch：安全正在变成验证工程，也是创业公司的机会

[查看原文](https://x.com/rauchg/status/2106516538836856945) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 认为安全会在软件公司里变成越来越大的职能，它同时是验证工程——比如“我的代码大概率是内存安全的”——和资本配置，即该把最多 token 投向哪个攻击面。他提出一个真实矛盾：AI 对手越来越老练，客户凭什么信任一个两人一狗的小公司；但反过来，全球网络安全状态糟糕、对中心化依赖加深，恰恰给了小团队大量可颠覆的领域。这条对做 AI Infra 和安全工具的 builder 有直接参考：安全能力正在从合规清单变成可工程化、可用模型验证的东西，小团队的机会在于把验证做成默认路径。
