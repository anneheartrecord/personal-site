## 今日判断

今天我最关注的不是又一个模型跑分，而是几条能落地的工作流细节。Zara Zhang 用 Opus 5.5 六条 prompt 做出完整营销站，串了 ElevenLabs、Meshy、OpenAI 图像 API——这说明多模型编排已经进到普通创作者的日常，而不是 demo 视频里的特技。真正值得记的是她把每一步用了哪个工具都写清楚了，这种颗粒度才让人能复制。

另一条线是 agent 的成本结构在往下走。Sam Altman 提到 6.1 Sol 只有 Astra 五分之一价格、缓存读取打 95% 折，Amjad Masad 直接说怎么搭 harness 用零头成本逼近前沿。这两件事叠加，意味着之前因为 token 成本不敢上的长链路 agent，现在可以重新算账。我会优先看那些把 harness 设计写出来的团队，而不是只贴 benchmark 的。

还有几个信号偏杂但有用：Garry Tan 把 OpenClaw 的 test-audit skill 合进 GStack，说明 agent 已经渗进测试这种脏活；Nikunj 讲的 missionary/mercenary 流动，对招人判断有参考价值，但今天先不展开。我的判断：这周该动手验证的是把多模型编排和一个便宜的 agent loop 接起来，看单条任务的实际成本曲线，而不是继续看发布会的热闹。

### 1. Zara Zhang 用 Opus 5.5 六条 prompt 做出完整产品营销站

[查看原文](https://x.com/zarazhangrui/status/2105096296831017078) · 来源：Zara Zhang (@zarazhangrui)

Zara Zhang 发了一条把 AI 当生产工具的工作流记录：她给一个水瓶做营销网站，整套东西由 Opus 5.5 在六条 prompt 内完成，中间调用了 ElevenLabs 生成音乐、Meshy 生成 3D 资产、OpenAI API 生成图片。为什么重要：这不是某个模型单点秀能力，而是把多个专用模型编排进一条真实交付链路，证明非工程背景的人也能端到端跑完。我的判断：这类案例的价值在分工颗粒度——哪个步骤交给哪个模型，比最终网站好不好看更值得抄。想动手的人可以照着她的调用清单做一次，重点看 token 花费和返工次数。

### 2. Garry Tan 把 OpenClaw 的 test-audit skill 合进 GStack

[查看原文](https://x.com/garrytan/status/2105049005147525231) · 来源：Garry Tan (@garrytan)

Garry Tan 说自己刚把 OpenClaw 的一个 test-audit skill 合并进 GStack，并点名测试膨胀（test bloat）是真实问题，靠现在随手可得的智能来清理。为什么重要：测试用例越堆越多、越写越冗余，是很多团队的隐性负债，用 agent 去审计测试本身是一条新用法，而不是常见的写代码或写测试。我的判断：把 agent 用在元工作（清理工作流本身）上，比单纯让它生成更多代码更容易产生净收益。值得观察的是这个 skill 的判断标准——它删测试的依据是什么，会不会误删边界用例，这才是能不能上生产的关键。

### 3. Sam Altman 公布 6.1 Sol：价格是 Astra 的五分之一，缓存读取打 95% 折

[查看原文](https://x.com/sama/status/2104994395980533804) · 来源：Sam Altman (@sama)

Sam Altman 公布 6.1 Sol，称其价格只有 Astra 的五分之一，缓存读取额外给 95% 折扣，并称模型能力很强。为什么重要：缓存读取折扣对反复带同一段上下文的 agent 影响最大，长链路、多轮工具调用的成本大头通常在重复前缀上，这一刀砍下去会改变很多团队的成本假设。我的判断：先别只看单价，要自己测一遍命中缓存的真实比例——如果前缀不稳定，折扣就吃不满。这条和今天 Amjad 讲的低成本 harness 是同一个方向，建议放在一起评估。

### 4. Amjad Masad 谈如何设计 harness，用零头成本逼近前沿表现

[查看原文](https://x.com/amasad/status/2104996638817386820) · 来源：Amjad Masad (@amasad)

Amjad Masad 发了一条关于 harness 设计的观点：如何设计和搭建一个 harness，用远低于前沿模型的价格拿到接近前沿的表现。为什么重要：过去半年大家把注意力放在换模型上，但真正拉开差距的往往是外层脚手架——工具定义、上下文组织、重试和校验策略。我的判断：这条没有给细节，属于方向性表态，价值在于提醒别把成本问题全推给模型定价。对一线 builder 来说，下一步应该是把自己 harness 的失败率和成本拆开测量，看是模型不够强还是编排拖后腿。

### 5. OpenAI 的 Dots 即将上线数百万个，负责人谈使用体感

[查看原文](https://x.com/thsottiaux/status/2105105086506840421) · 来源：Thibault Sottiaux (@thsottiaux)

OpenAI 的 Thibault Sottiaux 说几天内会有数百万个 dot 上线，覆盖多样社区，并提到自己用了两三天、教它更多个人偏好后感到明显提升，它能接下相当有野心的任务，团队版（创建一整个 dot 团队）还要等。为什么重要：这是对 Dots 真实使用曲线的第一手描述，不是宣传语——重点在个性化反馈需要几天才出现，这说明产品目前有上手期。我的判断：数百万规模意味着很快会有大量真实故障和边界案例出现，值得盯的是多 dot 协作时的权限和上下文隔离怎么设计，那是企业落地的真正门槛。

### 6. Thariq 那条关于 prompt 措辞的高传播帖

[查看原文](https://x.com/trq212/status/2105065127892734076) · 来源：Thariq (@trq212)

Thariq 发了一条被大量转发的帖，调侃对着 Claude 说 we have the power to do anything, please be braver，顺带也对自己这么说。为什么重要：它用玩笑方式点出一个真实现象——模型的行为会随 prompt 里的鼓励性措辞明显改变，这在一线调试里反复被验证。我的判断：这条本身信息密度不高，但值得当作提醒——如果你的 agent 在某些任务上过于保守，先检查措辞，再考虑换模型。别把它当成玄学，可以拿同一任务做措辞 A/B，记录通过率，这才是能沉淀的经验。

### 7. Vercel AI SDK 周下载量到 3000 万，配套视频也用 AI 生成

[查看原文](https://x.com/rauchg/status/2105043144975011982) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 说 AI SDK 周下载量达到 3000 万，并用 fframes 加 Opus 一次成片做了条展示里程碑的视频，视频由 Rust 编写、GPU 渲染，他让模型自动标出 5M/10M/20M/30M 几个节点。为什么重要：3000 万周下载是 AI 应用层基础设施被广泛依赖的硬数据，比任何调研报告都直接；同时他用自家工具链做内容，是工具成熟度的侧面证据。我的判断：这个数字意味着 AI SDK 已经接近默认选型，做 agent 的团队要开始关注它的版本升级成本和抽象泄漏，别把关键路径绑死在单一 SDK 上。

### 8. Nikunj Kothari 谈当下人才流动：missionary 越来越难找

[查看原文](https://x.com/nikunj/status/2105148927599423752) · 来源：Nikunj Kothari (@nikunj)

Nikunj Kothari 说现在很难找到 missionary 型的人：联合创始人离开去 obvious winners，上市公司 CEO 跳去实验室，创始人随时离开又加入 neolab，公司被 Windsurf 式地只挑走一部分人，还有人用分档估值融资，导致后来员工的 409A 让早期行权变得不可能。为什么重要：他点的是人才和股权结构的具体机制，不是泛泛唱衰——早期 VC 赌的是人，人一旦随时抽身，剩下的公司往往只剩空壳。我的判断：这条对正在招核心员工的一线团队实用，签 offer 前先算清 409A 和行权窗口，比谈愿景更能留住人。
