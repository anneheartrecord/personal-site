## 今日判断

今天最实的一条是 Claude Code 把 AGENTS.md 变成内建行为：v2.1.277 起，如果目录里没有 CLAUDE.md，它就去读 AGENTS.md，并且可以在 /config 里开关。这表面是兼容一个文件名，实际是 harness 开始分层——AGENTS.md 是内建 mod，而 mods 本身是可自定义的机制，你以后能自己写 project instructions 的加载逻辑。我关注的是这个信号：项目级上下文正在从单厂商私有文件变成可插拔约定，跨工具复用 instruction 的成本在下降。

第二条我盯的是 token 消耗的构成变化。Vercel AI Gateway 今天开放式模型占到 token 量 78.4%，Moonshot AI 和 DeepSeek 排到第 3、第 4，加上 Z.ai 后合计支出超过 OpenAI。这不是开放模型赢了，而是说明一旦价格压下来，agent 这类高频小请求会大量涌向便宜模型，推理支出结构正在被 agent 工作流重写，闭源模型被挤到高价值长尾那一侧。

剩下的我更多是当模式在看：Jev 这种小模型做分类和判断调用被反复 demo，Box 把 incident report 自动分级归档；Meta Muse 真去打电话砍掉有线电视账单；Peter Steinberger 的 roboclaw 常驻团队服务器、在 Discord 里同时协调多个 session。这些单条都不深，但放一起说明 agent 的落点已经从 demo 转向真实工作流里的具体动作——判断、协商、调度。我的判断是：接下来值得做的不是又一个 agent 壳，而是把这些判断点做成便宜、可观测、可回滚的基础设施。

### 1. Claude Code 开始读 AGENTS.md，项目上下文走向跨工具约定

[查看原文](https://x.com/trq212/status/2101009392611278961) · 来源：Thariq (@trq212)

Thariq 宣布 Claude Code 从 v2.1.277 起支持 AGENTS.md：如果某个目录里没有 CLAUDE.md，Claude 会去找并使用 AGENTS.md，这个行为可以在 /config 里开关。为什么重要：项目级 instruction 一直是各工具各写一份，AGENTS.md 被更多 harness 接受后，同一份上下文可以在不同 agent 之间复用，迁移和混用工具的成本明显下降。我的判断是，真正值得注意的不是多认一个文件名，而是 Claude Code 把这件事做成了 mod 机制——AGENTS.md 支持是内建 mod，用户可以自己写自定义版本。这意味着 harness 的可编程性在提升，谁能控制 project instructions 的加载逻辑，谁就能控制团队的实际工作流。可以开始把项目上下文往工具无关的方向整理。

### 2. Vercel AI Gateway 上开放模型 token 占比 78.4%，Moonshot 和 DeepSeek 进前四

[查看原文](https://x.com/rauchg/status/2101186741042663579) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 公布当天 Vercel AI Gateway 的 token 量构成：开放模型占 78.4%，闭源占 21.6%；按支出看，Moonshot AI 和 DeepSeek 排到第 3、第 4，加上 Z.ai 后合计支出超过 OpenAI。他特别标注这是跨 provider 的推理支出，不等于开放权重实验室的收入。为什么重要：token 量和支出给出两个不同信号，量上开放模型已经压倒性领先，说明 agent 这类高频小请求大量流向便宜模型。我的判断是，这轮变化的驱动力不是模型能力对比，而是价格——当 agent 把请求数放大几个数量级，成本结构就会自己重排，闭源模型会被推到高价值、低频的那一段。

### 3. Box 用 Jev 做企业分级：读 incident report，自动判断严重度并归档

[查看原文](https://x.com/levie/status/2101007708044574906) · 来源：Aaron Levie (@levie)

Aaron Levie 展示 Box 联合 Jev 的 demo：从 Box 拉一份 incident report，判断它是否面向客户、严重程度如何，然后把文件移进 escalate、monitor 或 review 目录，并写入 metadata template。整个流程几乎瞬时完成、成本极低。他列举的场景包括保险理赔、合同管理、贷款审批、安全审查和客户日志分析。为什么重要：这类工作以前要么靠人工分诊，要么靠脆弱的规则引擎，现在用便宜模型做一次判断调用就够了。我的判断是，这是 agent 最容易先赚钱的形态——不是替人做完整个任务，而是替人做流程中那一个判断点，价值密度高、失败可回滚、审计路径清晰。

### 4. Muse 打完电话砍掉 288 美元有线电视费，客服系统没准备好接 agent

[查看原文](https://x.com/petergyang/status/2101083891507593576) · 来源：Peter Yang (@petergyang)

Peter Yang 放出一段 Muse 打电话给 Comcast 协商有线电视账单的通话记录，最终拿到一年 288 美元的减免。他配文说，大多数公司的客服线路还没准备好接待 agent。为什么重要：这不是 demo 里的任务完成，而是 agent 在真实对抗性流程里拿到了经济结果——对方是人类客服，涉及议价、信息不对称和流程规则。我的判断是，语音 agent 最先规模化的场景很可能就是这类重复议价和账单处理，因为它结果可量化、失败无损失。同时这也意味着客服侧会被迫升级：当来电方是 agent，身份识别、会话记录和反滥用策略都得重做。

### 5. roboclaw 常驻团队服务器，在 Discord 里同时协调多个会话

[查看原文](https://x.com/steipete/status/2101141707375227372) · 来源：Peter Steinberger (@steipete)

Peter Steinberger 描述他的 roboclaw 部署：跑在团队服务器上，常驻 Discord，能和 gpt-live 对话，并且知道自己同时在处理的多个 session。开会时团队可以直接问它当前和历史 session 的上下文。为什么重要：大多数人还在本地跑单个 agent 会话，这里已经把 agent 变成有持久记忆、被多人共享的团队设施。难点不在接 Discord，而在多会话上下文的组织、检索和隔离。我的判断是，这种常驻、多会话的 agent 会先出现在小团队里，因为它的价值随会话数量增长，而大公司的权限和合规流程会拖慢这类尝试。想做的可以从 session 索引和上下文召回这一层切入。

### 6. 扩散模型之父 Stefano Ermon：推理速度和效率会是下一阶段的胜负手

[查看原文](https://www.youtube.com/@NoPriorsPodcast) · 来源：No Priors

No Priors 请到 Stefano Ermon，斯坦福教授、Inception 联合创始人兼 CEO，扩散模型方向的奠基者之一。他谈到自己从 2014 年在 MNIST 上做生成模型的经历，以及现在创业挑战大实验室的方向：未来几年 AI 竞争的关键是速度和效率。为什么重要：当 agent 把推理请求数放大到每天成百上千次，单次延迟和单位成本就变成产品能不能成立的前提，而不是优化项。我的判断是，这条值得听的不是观点本身，而是他作为扩散方向的原始作者对非自回归推理路线的判断——如果扩散在推理侧真的跑通，最先受益的会是高频调用、对延迟敏感的 agent 工作流，而不是聊天场景。
