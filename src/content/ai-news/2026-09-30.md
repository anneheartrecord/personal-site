## 今日判断

今天最值得记的一笔是 Sonnet 5.5 的发布，但我关心的不是跑分，而是几个一线团队给出的工程侧数据。Boris Cherny 说在 Claude Code 里修 bug 快了 30%、用量少 30%；Aaron Levie 说 Box 在企业内容评测上整体涨 4 分，交付到成品快 2.4 倍、token 少 12%，金融那块单任务甚至涨 48 分——这些是真实工作负载上的数字，不是 benchmark 截图。Dan Shipper 那边还给了个反向信号：他团队里有人觉得中等档模型的生存空间正在消失，因为便宜模型已经能打，贵的只在特定环节才值得上。这对做产品的人是直接的成本结构问题。

另一件我觉得被低估的事，是 Thariq 那句“现在没法给你看 prompt 了”。因为一个能用的工作流本来就是 references、skills、跨仓库检索、调外部 API 拼起来的，prompt 已经不是可迁移的资产。这跟 Thibault Sottiaux 宣布 Pro $200 订阅额度按 API 花费重算、实际上砍到一半，是同一件事的两面：模型本身在变便宜、变聪明，但你把智能组织成一个可复用系统的能力，才是真正要投入的地方。谁还停留在调 prompt、比单次调用价格，谁就会在下一轮里发现自己的东西没法沉淀。

我的判断是：接下来半年，builder 的护城河会从“用了哪个模型”迁移到“怎么把模型的性价比变化翻译成自己工作流的结构调整”。Sonnet 5.5 这种便宜又更省的模型，不是让你少花钱，而是让你敢在 workflow 里多放几层 agent 调用和动态编排。今天 Vercel 那笔迁移也是同一个逻辑：他们用 AI skills 做迁移，一周内完成一个成熟工作负载，还顺手把两个 skill 沉淀下来。真正的产出不是一个改动，是那套能被下次复用的流程。

### 1. Sonnet 5.5 在 Claude Code 里修 bug：快 30%，用量少 30%

[查看原文](https://x.com/bcherny/status/2104638725317923228) · 来源：Boris Cherny (@bcherny)

Boris Cherny 发了 Sonnet 5.5 在 Claude Code 里修一个 bug 的实测：速度快 30%，同时用量少 30%。这两件事一起出现很关键——通常模型变强会带来 token 消耗上升，但这里是同一任务既更快又更省，意味着单次修复的成本结构直接下降。对天天跑 coding agent 的人来说，这不是跑分，而是每天账单和等待时间的实际变化。我的判断是，cheap + smart 同时成立的模型会改变工作流设计：你可以更放心地把长链路、多轮修复、自动重试放进 agent 里，而不用太担心成本失控。真正要重新算的，是哪些原本因为贵而被人肉拆掉的步骤，现在可以交还给 agent。

### 2. Box 用 Sonnet 5.5 跑企业内容评测：交付快 2.4 倍，金融单任务涨 48 分

[查看原文](https://x.com/levie/status/2104648654074343480) · 来源：Aaron Levie (@levie)

Aaron Levie 说 Box 在复杂工作评测和 Box Agent 上早测了 Sonnet 5.5：整体涨 4 分，但到完成交付物快 2.4 倍、token 少 12%；行业层面金融 +18 分、法律 +7、生命科学 +8、公共部门 +7。他给的具体例子是金融服务里一个收购案的尽调审查，模型发现交易簿里的利息合计算错、期权定价也错，并且快了约 61%。这条的价值在于，它测的是企业文档类知识工作，不是玩具任务。我的判断是，企业在 Agent 上真正卡住的一直是“能不能信任它处理高价值文档”，而这类数字开始让那个门槛变得可谈判。对做企业 AI 产品的人，这是可以直接拿去做 ROI 讨论的素材。

<a id="20260930-03"></a>

### 3. Thariq：现在没法“给你看 prompt”了，工作流已经是引用、skills 和例子

[查看原文](https://x.com/trq212/status/2104608785696440510) · 来源：Thariq (@trq212)

Thariq 说，现在基本上不可能有人“给你看他的 prompt”，因为一切都在于 references、skills 和 examples。他自己会先让 agent 去看他做过的另外三个仓库，再搜 web 找参考，再调其他 AI API。这句话点破了一个正在发生的变化：prompt 作为可复制资产的时代已经过去，能复用的是一个组织好的智能环境。我的判断是，这对做 devtool 和 agent 平台的人是明确的方向信号——产品价值不在编辑器里那句提示词，而在你能不能方便地接入代码库、检索、外部 API 和可复用 skill。谁的集成面越宽，谁的工作流越难被别人抄走。

<a id="20260930-04"></a>

### 4. Cat Wu：Sonnet 5.5 在 Claude Code 里让用户多完成约 30% 任务

[查看原文](https://x.com/_catwu/status/2104639552170377399) · 来源：Cat Wu (@_catwu)

Cat Wu 说 Sonnet 5.5 上线后，Claude Code 用户完成的任务量比 Sonnet 5 多约 30%，因为它更聪明，同样的活儿需要更少 token。她给了一个扫院子树叶的工具调用例子：比 Sonnet 5 快 24 秒、少 6K token。这条和 Boris 那条互为补充，一个从任务完成量、一个从单任务成本看，指向同一个结论：模型效率提升正在直接转化为使用量的提升。我的判断是，这种“用户做得更多”而不是“模型更会答题”的指标，才是评估 coding agent 模型该看的维度。做同类产品的人，应该开始把任务完成率而不是单次准确率当成核心指标。

### 5. Dan Shipper：Sonnet 5.5 改了写作和迭代体验，但团队开始质疑中档模型的存在意义

[查看原文](https://x.com/danshipper/status/2104636728992776510) · 来源：Dan Shipper (@danshipper)

Dan Shipper 测下来 Sonnet 5.5 的写作比 Opus 5.5 都强，但在改写任务上 Astra 仍是他的首选；它更快更便宜，所以是 Kieran 做快速迭代编码和设计时的首选模型。关键的反向信号是，他团队里有人觉得自己的栈里已经没有中档模型的位置了——因为便宜的那档已经够聪明，贵的只在特定环节才值得上。我的判断是，这对做模型选型的人是个提醒：分层定价的中间层正在被两头挤压，产品如果把价值押在“比便宜的好一点、比贵的便宜一点”上，会很难守。要么在某个具体场景上做到最好，要么就把成本压到极致。

### 6. Thibault Sottiaux：Pro $200 重新开放，但 API 额度实际砍到一半

[查看原文](https://x.com/thsottiaux/status/2104823812042940713) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 说 Pro $200 订阅会对新用户重新开放，但同时改了使用量计算方式，折算下来实际 API 花费额度是旧方案的一半。他给的理由是：承诺不重新引入 5 小时限制，用户可以自由使用每周额度；同时保证随着模型变高效，会把价格下降传导下去，所以长期看每美元能做的事更多。我的判断是，这是一次典型的定价结构重排：表面维持订阅价，实际调整单位经济。对重度使用者来说，短期成本是上升的，但他们赌的是效率曲线继续往下走。做产品的应该把这种“额度规则会变”当成常态，别把自己的成本模型死死建立在某家订阅的具体数字上。

<a id="20260930-07"></a>

### 7. Vercel 开放域名搜索免鉴权，明确面向 agent

[查看原文](https://x.com/rauchg/status/2104764419305796094) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 宣布现在可以免鉴权搜索 Vercel 域名，并特意点出这对 agent 尤其好用。这条很短，但方向明确：基础设施正在开始为 agent 而非人做接口设计，去掉鉴权这层摩擦意味着 agent 可以直接查询和调用。我的判断是，这类小改动会越来越多，而它们累积起来会定义 agent 时代的 API 形态——更少鉴权、更结构化、更适合机器读写。做 devtool 的人如果还在按人类开发者体验来设计 API，会慢慢发现自己的接口不被 agent 友好地调用。

### 8. Vercel 迁移复盘：构建快 70%、渲染快 75%，并沉淀出两个 AI skill

[查看原文](https://x.com/rauchg/status/2104660502723072281) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 说他们以尽量少的人工干预完成了一次迁移，结果是构建快约 70%、首屏渲染快约 75%，而且从迁移过程中提炼出两个 AI skill 会对外分享。他强调这是一个成熟工作负载、带着很多原供应商特有的写法，但净工作量在一周内完成。我的判断是，这条最值得关注的是那两个被沉淀下来的 skill——真正的收获不是迁移结果，而是下次迁移能复用的流程。这跟今天 Thariq 说的“prompt 不是资产、工作流才是”是同一个逻辑。对团队来说，做 AI 辅助工程时应该有意识地把过程抽成可复用资产，否则每次都在重新发明轮子。
