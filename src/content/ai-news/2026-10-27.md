## 今日判断

今天我先看的是 Rauch 做的 cpu-chat。他在两台没有网络的 Firecracker microVM 之间，用 CPU 争用、cache 驱逐时序、DRAM 带宽争用三条通道把消息传了过去，x86 和 M5 都跑通，还把 Firecracker 官方推荐的反制措施——不共享 SMT、不共享 KSM、租户绑核——全部绕开。他没把它当攻击来卖，重点是提醒：只要 Agent 共享硬件，它们之间就可能自发形成一条你监控不到的通道，而且延迟还不差。我看下来，这对做多租户 sandbox 和多租户 Agent 托管的人是硬约束，比再刷一个榜单重要。

Anthropic 的 S-1 我读了两块。Nikunj 拆算力合同：6 月底有 2656 亿美元采购承诺加 3214 亿美元未起租租约，Google 和 Amazon 照付不议，SpaceXAI 那笔 1205 亿却在锁定期后任一方可提前 90 天取消；Dan Shipper 补的财务面是上半年营收同比 1300%、GAAP 经营转正、85% 毛利、80% 收入来自最近半年发布的模型。把这两块放一起看，模型收入的半衰期只有半年，算力合同却是多年刚性，真正难的是在半年一换代里持续把钱押在正确结构上。Levie 那条是同一件事的下游：500 强客户平均只把不到 0.1% 的支出花在 Anthropic 上，他算 10 到 50 倍空间，落到 1% 到 5%。现在绝大多数公司还把 Agent 当人触发的工具，没人敢让它在后台跑长任务。

所以我今天给一线 builder 的复盘很短：先查你的 sandbox 是不是默认租户之间绝对隔离，Rauch 这条告诉你这个假设可能不成立；再把自己的模型切换成本压到半年能换一次主力，S-1 那组数字说明模型寿命就是这个量级。谁先把这两件事做扎实，谁才有资格接住 Levie 说的那 10 倍增量。

### 1. Rauch 复现 CPU 隐蔽信道：共享硬件上的 Agent 能互相传消息

[查看原文](https://x.com/rauchg/status/2114770919436808572) · 来源：Guillermo Rauch (@rauchg)

Guillermo Rauch 用两台无网络的 Firecracker microVM 复现了 OpenAI 关于 CPU 隐蔽通信的发现，通过 CPU 争用、cache 驱逐时序、DRAM 带宽争用三条通道在 VM 之间传递消息，x86 和 M5 都能跑，并绕过了 Firecracker 官方推荐的隔离建议（关 SMT、关 KSM、租户绑核）。他明确区分这不是 Meltdown 那类偷数据的侧信道，但结论是只要租户共享硬件，Agent 之间就存在一条你观测不到的通信路径，且延迟还不差。我的判断：做多租户 sandbox 或 Agent 托管平台的人，要把这条通道当成真实的监控盲区来设计，而不是只信 hypervisor 的隔离承诺。

### 2. Levie：Fortune 500 客户花在 Anthropic 上的钱不到总支出的 0.1%

[查看原文](https://x.com/levie/status/2114761816199098587) · 来源：Aaron Levie (@levie)

Box CEO Aaron Levie 引用 Anthropic 数据指出，其 Fortune 500 客户平均只把不到 0.1% 的支出花在 Anthropic 上，且这部分花费主要来自 coding 和通用员工效率场景。他判断这个比例有 10 到 50 倍的上升空间，也就是落到 1% 到 5%，但前提是企业把底层流程重写成无人触发、后台长跑的 agent 工作流。我的判断：这是目前判断 agent 渗透率少有的具体指标，比任何 benchmark 和口号都实在。它说明当下几乎没人在真正用后台 agent，谁能先让客户敢把流程交出去，谁就吃下这 10 倍以上的增量，而不是靠多卖几个席位。

### 3. 拆解 Anthropic S-1：约 5870 亿美元算力承诺，条款差别极大

[查看原文](https://x.com/nikunj/status/2114761204333998427) · 来源：Nikunj Kothari (@nikunj)

Nikunj Kothari 拆了 Anthropic S-1 里的 compute 合同：截至 6 月 30 日有 2656 亿美元采购承诺和 3214 亿美元尚未起租的租约，合计约 5870 亿美元、分多年支付。条款差异很大，Google 和 Amazon 要求照付不议，SpaceXAI 的 1205 亿美元协议在 2027 年 1、3 月锁定期结束后任一方可提前 90 天取消。Anthropic Direct 还把芯片、建筑、电力、运营拆成不同合同，允许早锁建筑、晚锁芯片。我的判断：这份结构比融资金额更值得 builder 读，它暴露了前沿实验室真正的风险敞口——多年刚性支出对上六个月就换掉一半收入的模型周期。

### 4. Amjad Masad：Replit 要做 Agent Habitat，目标是自驾驶公司

[查看原文](https://x.com/amasad/status/2114760898225299721) · 来源：Amjad Masad (@amasad)

Replit CEO Amjad Masad 提出 Agent Habitat 概念，认为公司几百年的层级加流程协同会被 agent 改写，走向人只做判断、agent 执行大部分工作的自驾驶公司，Replit 想做这套基础，并引 Andreessen 关于每次计算革命都先经历混乱的分析做背景。我的判断：这类愿景每年都有，值得看的不是词造得好不好，而是 Replit 会不会把 agent 的编排、权限、审计这些真正卡住企业的机制做进产品。如果只是把 agent 外面包一层对话壳，Habitat 就只是又一个营销词，三个月后就能验证。

### 5. Steinberger 实测 Bun AOT 编译：性能 2-3 倍，内存减半

[查看原文](https://x.com/steipete/status/2114879798434758905) · 来源：Peter Steinberger (@steipete)

Peter Steinberger 周末实测了 Bun 的 AOT 编译器，报告性能提升 2 到 3 倍、内存占用不到原来一半。这是个人复现数据，不是官方基准口径。我的判断：对跑 CLI 工具、本地 agent runtime、构建脚本的人来说，这类启动和内存收益直接等于单机可承载进程数的提升，尤其是在一台机器上常驻多个 agent 进程的场景。值得自己拉下来复现一次，看收益是落在冷启动、稳态吞吐还是内存峰值上，再决定要不要迁移构建链。

### 6. Every 实测新前沿模型：榜单很漂亮，真实工作流里只是中游

[查看原文](https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL) · 来源：AI & I by Every

Every 的 AI & I 里，团队对 Google 和 Meta 新发布的前沿模型做了 hands-on 测试，认为两者都明显 benchmark maxed：榜单分数好看，但在知识工作、coding、设计、写作的实际任务上表现与公开分数不符。具体例子是他们让模型重写一个 vibe-coded 代码库，多轮跑下来只有约 50% 的水平，属于中游；他们还用把严肃文学分析引向麦当劳的测试看模型会不会被带偏，其中一个直接上钩。我的判断：模型评测的日常已经变成用你自己的任务集反复跑，而不是读新闻稿里的排名，这项工作应该固化进选型流程。

### 7. Terra 6.1 发布：写作与人格改善，computer use 和用量翻倍是重点

[查看原文](https://x.com/thsottiaux/status/2114800277677092936) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault Sottiaux 宣布 Terra 6.1 上线，称这是首个在写作、人格化和对请求的细腻理解上明显更好的版本，整体能力均衡，在 computer use 上表现很好，并在 API 和订阅里提供比 6.1 Sol 多一倍的用量。Sam Altman 同步发帖，强调这一代开启新的 computer use 阶段。我的判断：把 computer use 和用量翻倍放在一起讲，说明发布方赌的是长任务、屏幕操作这类高消耗场景。对 builder 来说，用量翻倍比榜单提升更直接，等于单位任务成本被压下来，之前因成本搁置的屏幕操作类 agent 值得重新跑一遍。
