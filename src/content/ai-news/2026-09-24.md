## 今日判断

今天最直接的信息是成本曲线又断了一次。Opus 5.5 在 Claude Code 和 Claude App 里转默认（medium effort 对齐 Fable 5.1 的智力但更快，rate limit 多跑 25%），同时 Box 在真实企业任务上测出 63% fewer tokens、42% 更少废话、30% 更快；GPT-6 Sol/Luna 把 API 价格永久砍半。我看下来这不是两个 PR 撞车，而是同一件事：单位任务成本在往下跌，Jevons 那套在 agent 上正在应验——能上 agent 的场景变多了。

我自己更关注的是 builder 怎么花这笔省下来的预算。Boris 用 Opus 5.5 加 Lean 做形式化验证，短提示就换来 16 个修 race condition 的 PR；他不懂 Lean 也能跑通，这比任何 benchmark 都实在。Rauch 挂了 4 个模型跑 Next.js eval，97% 那档有三家并列，但 Grok 便宜 2-7 倍——对做工具的人来说，选型逻辑已经从谁能做变成单位正确率多少钱。

我的判断：接下来一周真正拉开差距的不会是 prompt 花样，而是把 token 预算重新分配到验证、评测和原型上。Thariq 那句不是发 10x 功能，而是花更多时间理解用户和试原型，配着今天的降价读特别顺。给一线 builder 的复盘就一句：先算你的任务单价，再决定哪些以前跑不起的 agent 环节现在可以真的上。

### 1. Opus 5.5 成为 Claude Code 与 Claude App 默认模型

[查看原文](https://x.com/_catwu/status/2102437713781944397) · 来源：Cat Wu (@_catwu)

Claude Code 和 Claude App（含 Cowork）在 Pro、Max、Team 计划下把 Opus 5.5 设为默认。产品侧给出的关键数字是：全产品默认 effort medium，智力对齐 Fable 5.1 但更快；Opus 5.5 的 rate limit 比 Opus 5 多跑 25%。为什么重要：对每天挂着 coding agent 的人来说，默认模型的切换等于工作流基线变了，effort medium 意味着速度与智力的默认取舍被产品化。我的判断：这类默认更新比发布会更值得跟，因为你不需要改配置，成本结构就变了；建议这周把自己的长任务重跑一遍，确认 25% 的额度余量是否真的落在你的用量模式上。

### 2. Box 在真实企业任务上测 Opus 5.5：token 少 63%、快 30%

[查看原文](https://x.com/levie/status/2102448415775051790) · 来源：Aaron Levie (@levie)

Box 用自家 Box Agent 在非结构化数据的企业知识工作上测 Opus 5.5，对比 Opus 5：token 用量减少 63%、verbosity 降 42%、快 30%，且模型本身更便宜。举的例子包括金融服务尽调（找定价工具里的每一处算错）任务准确率 +39%，在字数减半的情况下每次尝试都满分，整体 token 少 82%。为什么重要：这是 agent 进企业工作流时最真实的指标——不是答对没答对，而是答对要烧多少钱和多少时间。我的判断：省钱加更少 verbosity 才是 agent 能做长链路的前提，verbosity 高会连带 tool call 变多、上下文被废话吃掉；做企业 agent 的人应该照这套任务口径重跑自己的 eval。

### 3. 一天内 frontier 价格两连降，agent 用例开口变大

[查看原文](https://x.com/levie/status/2102477253070430322) · 来源：Aaron Levie (@levie)

同一天里 Opus 5.5 降价、GPT-6 Sol 和 Luna 把 token 价格砍 50%。Levie 的判断是单位任务成本下降速度在技术史上没有先例，每次成本下来，能部署 agent 的场景就明显变多，并把 Jevons paradox 落到 agent 上：用 agent 处理全部数据、扫代码安全、读日志做决策、多 agent 编排。为什么重要：对 builder 来说这是预算重新分配的信号，以前因为贵而砍掉的环节现在可以加回来。我的判断：不要只当新闻看，把它换算成自己产品里每个 agent 任务的单价，挑一个之前因成本搁置的环节，这周上线试一次，这才是降价真正该产生的动作。

### 4. 用 Opus 5.5 给 Claude Agent SDK 做形式化验证，换来 16 个修 bug PR

[查看原文](https://x.com/bcherny/status/2102543349102338309) · 来源：Boris Cherny (@bcherny)

Boris 用 Opus 5.5 对 Claude Agent SDK 做形式化验证，Lean 跑出 16 个 PR 修各种 bug 和 race condition，TLA+ 也有效，他会把两者结合排查数据流、并发和状态管理问题。关键细节是：他本人不熟这两种语言，但模型很擅长。为什么重要：这把 AI coding 从写业务代码推到验证与并发推理这类人类容易漏的领域，产出是修 bug 而不是补功能。我的判断：形式化验证对 agent 这种充满并发和状态的工具是低投入高回报，短提示换来真实 race condition 修复；建议把关键 infra 模块先跑一遍，不要等它自己出线上事故。

### 5. GPT-6 Sol 与 Luna 发布，API 价格永久减半

[查看原文](https://x.com/thsottiaux/status/2102463847714247142) · 来源：Thibault Sottiaux (@thsottiaux)

GPT-6 Sol 和 Luna 发布，官方说法是全面显著提升，写作和整体质感也更好，API 价格永久降 50%，让两个模型都进入新的用例区间。另外给 Plus、Pro、Business 用户账户里装了一次 banked reset。为什么重要：永久降价比限时优惠更有决策价值，意味着可以据此改产品定价和默认调用策略，额度重置则直接影响这周的试验预算。我的判断：和 Opus 5.5 放一起看，两家在同一天压价说明推理成本战还在加速；做产品的人现在应该按新价重算毛利，而不是继续用上季度的成本假设。

### 6. Next.js 新 eval：三家并列 97%，Grok 便宜 2-7 倍

[查看原文](https://x.com/rauchg/status/2102519097770885231) · 来源：Guillermo Rauch (@rauchg)

Vercel 跑了新一轮 Next.js eval：Opus 5.5、GPT 6 Sol、Fable 5.1 三家都是 97%，Grok 4.7 是 94%，但 Grok 便宜 2 到 7 倍。为什么重要：当头部三家在真实框架任务上打成平手，选型变量就从能力转到单位正确率的成本，而这正是 builder 每天要做的取舍。我的判断：94% 对 97% 在多数生产场景里不是决定性的，价格差 2-7 倍才是；如果你的任务能容忍 3 个百分点的差距，默认路由应该重新排，把高价模型留给真正难的那一档请求。

### 7. HAProxy C 转 Rust 实测：Opus 5.5 比 Fable 5.1 省 51% 且更快

[查看原文](https://x.com/bcherny/status/2102439069053747549) · 来源：Boris Cherny (@bcherny)

Boris 让 Opus 5.5 和 Fable 5.1 分别把 HAProxy 从 C 移植到 Rust，两者都几乎通过了 HAProxy 的全部测试，但 Opus 5.5 用 9.5 小时完成，Fable 5.1 用了 12 小时，且 Opus 5.5 成本低 51%。为什么重要：这是少见的同任务对照，把模型差异从主观体感变成可比的完成时间与成本，直接对应长时任务该派给谁。我的判断：模型选型现在要按任务类型分开看，长周期重构这类跑几小时的活，51% 成本差会被放大成真金白银；如果你有大型迁移 backlog，值得用这个口径先做一次对照再批量派活。

### 8. 模型变强后，正确的用法是不多塞功能，而是多做理解和原型

[查看原文](https://x.com/trq212/status/2102548686303854790) · 来源：Thariq (@trq212)

Thariq 的观点是：模型能力变强后，正确的做法不是往 prod 里塞 10 倍功能，而是花更多时间理解用户、做实验、搭原型、搞懂自己不懂的东西，从而发出真正能用的东西。为什么重要：这条和今天的成本下降是配套的——省下来的 token 预算如果不改用途，只会被拿去堆功能，然后变成维护债。我的判断：这句话对一线 builder 最有用的部分是它给了预算再分配的方向，把省下来的算力投到原型的数量和迭代速度上；结合前面的降价数据，这周就该把多出来的额度花在试原型，而不是多上线几个半成品。
