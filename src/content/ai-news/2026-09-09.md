## 今日判断

今天看下来，几条动态其实串成同一个判断：AI 已经过了‘能不能造’的阶段，反而卡在‘该造什么’和‘怎么让 Agent 真正协作’上。Aaron Levie 那条提醒要按能力再涨几个数量级来规划产品，我认同，但更具体的信号是从 Replit、Vercel 到 Codex 团队都在解决 Agent 的工作流问题——不是模型能力，而是 review、测试、QA 这些工程瓶颈。另一个感触是 Peter Steinberger 吐槽上游要求改 PR 还得人肉 ping Agent，这揭示了现在 Agent 协作的荒诞：我们有了自动写代码的 Agent，但代码评审和合并的流程还停留在人类时代。真正的下一代工具，应该是 Agent 对 Agent 的评审、合并，人类只做仲裁。Guillermo 的 agent-browser 强调‘软件工厂需要高质量视频录制’，也指向同一个方向：Agent 在评审、测试时需要可追溯的视觉证据。我的判断：接下来半年，Agent 的最大增量不在模型，而在围绕工程流程的基础设施——编码、评审、测试、部署的闭环自动化。

### 1. Levie：按能力数量级提升来规划产品

[查看原文](https://x.com/levie/status/2097189559712837770) · 来源：Aaron Levie (@levie)

Aaron Levie 提醒：AI 进步速度极快，应该按至少几个数量级的能力或 token 量提升来规划产品。最好的机会是用今天勉强可行的技术给客户创造价值，但完整愿景在当下技术下几乎不可能。很多产品需要数量级以上的数据处理或模型能力进化。建议 builder 瞄准这样的场景。

### 3. Guillermo Rauch 宣布 35 个开源资助，聚焦 Agent 技能与本地 AI

[查看原文](https://x.com/rauchg/status/2097116011384426516) · 来源：Guillermo Rauch (@rauchg)

### 4. Levie：AI 带来的是职业增长而非替代

[查看原文](https://x.com/levie/status/2097004960307449937) · 来源：Aaron Levie (@levie)

Aaron Levie 指出，AI 的自动化适用于需求无限的领域，因此创造了更多岗位而非取代。AI 尽管能替代部分工程师、律师工作，但也催生了网络安全、FDE、Agent 操作员等新职位。需求持续被发现，趋势是否会反转还不确定。

### 5. 投稿 PR 后要求人工 ping？Agent 协作时代该重审流程

[查看原文](https://x.com/steipete/status/2097091456234111377) · 来源：Peter Steinberger (@steipete)

Peter Steinberger 抱怨：用 Agent 往上游项目提交了 PR，对方要求一些修改，还得人工再 ping 一遍自己的 agent 让改。他质疑这种工作流的意义。这凸显了当前 Agent 协作的局限：评审过程仍需人类中介，浪费大量时间。
