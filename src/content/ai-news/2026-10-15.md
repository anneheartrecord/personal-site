## 今日判断

今天刷下来最值得说的还是 Gemini 4 Argon 这一波。Rauch 说 coding agent 是 AI 的 killer app，这话没错，但他后半句更重要：保持 model agnostic、gateway-maxxx。同一批候选里 Dan Shipper 拿自家 senior engineer benchmark 一测，Gemini 4 Argon 只有 21%，远低于 Sol 6 甚至 Muse。一端是 Levie 在 Box 的复杂企业文档任务里测出 14 个百分点的提升，另一端是 Shipper 在真实工程任务上直接打脸。我的判断是，模型发布的榜单和厂商 demo 已经彻底不能替你选模型了，每个人手里的 eval 才是唯一可信的东西。你要是没有自己的 benchmark，就只能跟着别人的叙事走。

Swyx 那条 How to Kill Your SaaS 我看了几遍。他们拿一个年费 4.3 万美金的真实 SaaS，开了场全球黑客松，周末克隆，用 AI 和真人双评，72 份提交、约 100B tokens，最后给出结果。这比所有关于 SaaS 会不会死的理论讨论都实在，因为他们把 midtier SaaS 到底哪部分难、哪部分已经被 token 吃掉，用真金白银的 contest 测出来了。这种一手数据比任何行业报告都值得沉淀成周度判断的素材。

另外几条我留意到 Thibault 说 ChatGPT 和 Codex 桌面端把磁盘占用砍了 60%，这是纯 power user 反馈驱动的 ship，小但真实。Anthropic 说的 redesigning source control 只有一句标题，但值得蹲原文，因为 source control 怎么为 agent 重构，会直接影响 coding tool 的形态。Aaron Levie 关于 cyber 会是 agent 最大场景之一的判断，机制讲得清楚：攻击面扩大一百倍，但防守端也能用 agent swarm 扫每一行代码。这条我留着观察，安全类 agent 大概率是接下来一年最实在的变现方向之一。

### 1. Rauch：coding agent 是 AI 的 killer app，但别把赌注押在单一模型上

[查看原文](https://x.com/rauchg/status/2110044152482365747) · 来源：Guillermo Rauch (@rauchg)

Rauch 恭喜 Gemini 团队，重申不要低估 Google，同时给出一个更值得抄的判断：所有人已经合理地把重心转回 coding，coding agent 就是 AI 的 killer app。他说连续看到 Muse Wonder 和 Gemini Argon 两个强模型之后，个人和公司都应该坚持 model agnostic 并且把 gateway 做到极致。为什么重要：模型迭代速度已经快到任何单一绑定都会变成负债，产品侧要能随时换后端。我的判断是，这条不是站队 Google，而是给所有做 coding tool 和 agent 产品的人一个直接建议——把 gateway 层做厚，把模型选择做成运行时决策，而不是产品发布时的架构决定。

### 2. Levie：Box 实测 Gemini 4 Argon，企业文档任务提升 14 个百分点

[查看原文](https://x.com/levie/status/2110046686198550539) · 来源：Aaron Levie (@levie)

Levie 说 Box 用 Gemini 4 Argon 在自己的 Complex Work eval 上测了一周，比 Gemini 3.1 Pro 整体涨了 14 个百分点，稳在前沿。他们的评测方式是让 Box Agent 处理跨行业的企业文档任务，接近知识工作者每天要做的难活。Gemini 4 在数学、逻辑、分析、业务领域知识上都有明显提升，而且更愿意把任务跑完而不是中途停下。为什么重要：企业 agent 最怕的就是任务执行不完整，Levie 特意点出这一点，说明这是他们选型的核心指标。我的判断是，企业场景的 eval 正在变成模型厂商之外最硬的第三方证据，比公开榜单靠谱得多，做企业 agent 的人应该去看这条的完整样例。

### 3. Swyx：拿一个年费 4.3 万美金的真实 SaaS，开黑客松看它能不能被干掉

[查看原文](https://x.com/swyx/status/2110065576764686421) · 来源：Swyx (@swyx)

Swyx 在 Latent Space 播客里放出了 Kill My SaaS 黑客松的结果。他们挑了一个自己每年花 4.3 万美金在用的 SaaS，让全球参赛者用一个周末去克隆它，AI 和真人双评测，任何模型任何 harness 都行，最终收了 72 份提交，烧掉约 100B tokens。他们分享的数据里有 midtier SaaS 到底哪部分还是难被替代，哪部分已经被 token 干掉，还有对获胜者的定性访谈。为什么重要：关于 SaaS 会不会死，绝大部分讨论都是理论，这是少见的用真金白银和真实评测跑出来的实验。我的判断是，这类一手 dataset 比任何行业预测都值得反复读，因为 midtier SaaS 的替代边界在哪里，直接决定了很多 AI 产品的定位。

<a id="20261015-04"></a>

### 4. Dan Shipper：Gemini 4 Argon 在自家 senior engineer benchmark 上只有 21%

[查看原文](https://x.com/danshipper/status/2110056016872427944) · 来源：Dan Shipper (@danshipper)

Dan Shipper 测了 Gemini 4 Argon 在他们内部的 senior engineer benchmark 任务上，结果只有 21%，远低于 Sol 6，甚至低于 Muse。为什么重要：同一天里 Levie 在 Box 的企业文档 eval 上测出 Gemini 4 提升 14 个百分点，Shipper 在真实工程任务上却测出 21% 的低分。这说明模型能力高度依赖任务分布，厂商 demo 和公开榜单完全不能替你选模型。我的判断是，这条要和 Levie 那条一起读，两个一线 builder 用各自的 eval 得出相反结论，这就是当下模型选型的真实状态：你必须有自己的一套 benchmark，否则你只是在跟着别人的叙事做技术选型。

### 5. Levie：cyber 会是 AI agent 最大的场景之一，攻防两端都被重构

[查看原文](https://x.com/levie/status/2110227571090788526) · 来源：Aaron Levie (@levie)

Levie 说 cyber 未来会是 AI agent 最大的空间之一。机制上有两个方向：一方面 agent 能顺着任何裂缝找到目标，软件漏洞和攻击面扩大一百倍；另一方面 agent swarm 可以审查每一行代码、测试任意排列组合的漏洞、比人更快地研究正在发生的安全事件。企业里安全团队永远招不够人，也永远清不完已知风险积压，agent 第一次给了更全覆盖的可能。为什么重要：这是少数把安全 agent 的商业逻辑讲清楚的判断，不是喊趋势，而是解释了为什么这块需求天然存在。我的判断是，安全类 agent 大概率是接下来一年最实在的变现方向之一，因为它对应的是企业长期存在、无法靠人力填满的明确缺口。

### 6. OpenAI：ChatGPT 和 Codex 桌面端磁盘占用砍掉 60%

[查看原文](https://x.com/thsottiaux/status/2110151780478927344) · 来源：Thibault Sottiaux (@thsottiaux)

Thibault 说他们优化了 ChatGPT 和 Codex 桌面端在磁盘上存储状态的方式，占用减少 60%。他明说这是个小 ship，但收到了足够多 power user 关于磁盘空间不够的反馈。为什么重要：这条本身信息量不大，但透露了一个信号，就是 coding agent 桌面端已经是重度使用的场景，用户会遇到磁盘被吃满的现实问题。我的判断是，这类以用户反馈驱动的小 ship 比大功能发布更能说明产品成熟度。做 coding tool 的人可以留意一下自己的本地状态存储策略，agent 会话和缓存的磁盘占用很快会变成 power user 的抱怨点。

### 7. Anthropic：在为 agent 重新设计 source control

[查看原文](https://www.anthropic.com/engineering/redesigning-source-control) · 来源：Anthropic Engineering

Anthropic Engineering 发了一篇题为 Redesigning source control at Anthropic 的文章。目前只有标题，没有更多细节。为什么重要：source control 是 coding agent 和开发者工具的地基，一旦 agent 开始大规模提交代码，现有的 git 工作流和评审机制都会暴露问题。如果 Anthropic 在内部真的重新设计了 source control 来适配 agent 协作，那这套思路会对整个 coding tool 生态有参考价值。我的判断是，先记下这条，等原文细节出来再深入看。source control 怎么为 agent 重构，会直接影响下一代 coding tool 的形态和协作协议，是值得长期跟踪的方向。
