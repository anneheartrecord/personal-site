## 今日判断

今天我看下来，最值得记的不是哪家模型又涨了几个点，而是几个把 AI 塞进真实工作流的人给出的具体反馈。Boris Cherny 说 Claude Code Review 跑在他所有 PR 上、几乎在合并前就抓掉大部分 bug，这个信息比任何 benchmark 数字都实在——它说明代码审查正在从人肉环节变成自动守门环节，团队的提速不是因为写代码变快，而是因为返工变少。我今天更关注这种卡在流程节点上的产品，而不是又一个能生成漂亮 demo 的东西。

Aaron Levie 讲的递归自我改进，我认同一半。模型能力超过多数工程师、harness 和 infra 支持长任务、数据变多、agent 能并行铺开更多任务和测试，这个飞轮机制是成立的；但他说要按 RSI 定价，我会谨慎。真正的瓶颈往往不在生成能力，而在判断什么值得做、以及谁来为并行跑出来的结果负责。Replit 把部署搬进客户自己的云、数据不出门，也是同一个方向：信任和边界变成企业落地的先决条件，而不是附加功能。

给一线 builder 的判断：接下来一两个月，评价一个 AI 产品该看它有没有嵌进哪个具体的手工环节、并且让人敢放手。Code Review 是模板，agent 做 DevOps 是另一条线。纯生成能力已经便宜了，编辑和监管能力才是没有供给的部分。我自己会把注意力放在能减少返工和减少人工盯盘的工具上。

### 1. Boris Cherny：Claude Code Review 跑在我所有 PR 上，几乎抓掉每个 bug

[查看原文](https://x.com/bcherny/status/2111158313463525518) · 来源：Boris Cherny (@bcherny)

Claude Code 团队成员 Boris Cherny 说，他已经无法想象没有 Claude Code Review 的生产方式：它跑在他所有的 PR 上，几乎在代码合入前就抓掉每个 bug，是他和团队既能提速又能抬高代码质量的部分原因。为什么重要：这把讨论从写代码的生成能力，拉到了代码合并前的自动守门这一个具体环节，返工减少才是团队真正感受到的增速来源。我的判断是，代码审查会先于代码生成被 agent 接管，因为它边界清晰、结果可验证、失败了也容易回滚，是当前 ROI 最明确的一类 agent 落点。

### 2. Aaron Levie：模型训练超过人类工程师的飞轮已经能看到了

[查看原文](https://x.com/levie/status/2111312141609586862) · 来源：Aaron Levie (@levie)

Aaron Levie 认为 AI 训练模型的能力已经在迅速超过人类工程师。他给出的机制是：模型能力超过多数工程师、长任务 agent 的 harness 和 infra 变强、可用数据变多、以及能并行铺开远多于人的任务和测试，这几件事叠成飞轮，会加速前沿模型推进。他提醒不按 RSI 定价可能是错的。我的判断是，飞轮机制成立，但边界在判断力和责任归属：并行跑一百个实验容易，决定该追哪个方向、以及谁为结果负责仍然稀缺。builder 该准备的不是更多算力，而是评估和验证的流水线。

### 3. Replit 把部署搬进客户自己的云，数据不出门

[查看原文](https://x.com/amasad/status/2111267314012496121) · 来源：Amjad Masad (@amasad)

Amjad Masad 宣布 Replit 可以部署到客户自己的云，数据始终不离开客户环境，明确面向政府、金融、医疗这类高风险场景。为什么重要：AI coding 工具过去卡在企业采购上的，往往不是能力而是数据驻留和合规边界。我的判断是，把部署权和数据所有权交还给客户，是这类工具从个人开发者走向受监管行业的必经一步，但代价是运维复杂度和版本碎片化会转嫁给团队，能不能撑住要看它有没有把交付做成可复制的标准件。

### 4. Garry Tan：一个起步项目，agent 同时写代码和搭 DevOps

[查看原文](https://x.com/garrytan/status/2111235500568969451) · 来源：Garry Tan (@garrytan)

Garry Tan 说今天开始一个新项目，最爽的是用 capydotai 加 AsideAI，让 agent 一次把第一版代码写好，同时把 DevOps 环境也搭起来。为什么重要：这不是单点生成，而是把写代码和搭基础设施这两个原本要切换工具、切换心智的环节串成一次调用，说明 agent 的价值开始体现在跨工具的串联上。我的判断是，谁能在项目从零到可部署这一段把 agent 链做顺，谁就能吃掉早期开发者最烦的那段启动开销，但这也要求工具之间有干净的接口，而不是靠人工来回粘贴。

### 5. Boris Cherny：做 PPT 已经不再搜 iPhone 边框 SVG

[查看原文](https://x.com/bcherny/status/2111158659971699136) · 来源：Boris Cherny (@bcherny)

Boris Cherny 说他现在做 slide deck 都用 Claude Slides，再也不用像以前那样去网上搜 iPhone 边框的 SVG。为什么重要：这是一个很小的细节，但它折射出模型产品正在从对话窗口渗进具体交付物，尤其是演示文稿这种高频、低风险、结果一眼能验的场景。我的判断是，这类轻量交付场景会最先被吃掉，因为它们失败成本低、验收标准清楚；但对 builder 的启示是，不要只做聊天界面，要把输出直接变成可用的文件形态。

### 6. No Priors 对话 Greg Brockman：软件变便宜之后，安全支出要超过软件支出

[查看原文](https://www.youtube.com/@NoPriorsPodcast) · 来源：No Priors

Greg Brockman 在 No Priors 里说，软件本身正变得极其便宜，所以人们要的不再只是软件，而是可靠、安全、可信的软件，因此安全支出应当远大于软件支出。他还谈到 OpenAI 的数学进展、Astra，以及 AI 现在能生成真正的新知识。我的判断是，这个论证的前提是生成代码的成本趋零，于是价值从写得出来转向敢不敢跑在生产上；对 builder 来说，这意味着安全、审计、可观测这些配套能力会变成产品差异点，而不是事后补丁。

### 7. Thibault Sottiaux：ChatGPT Space 由真实团队出镜，向用户征集下一步

[查看原文](https://x.com/thsottiaux/status/2111249534072529256) · 来源：Thibault Sottiaux (@thsottiaux)

OpenAI 的 Thibault Sottiaux 介绍 ChatGPT Space，承认呈现方式有时略显尴尬，因为出镜的就是真正在做这个产品的团队，并直接问用户接下来想看什么。为什么重要：这是产品团队绕开公关稿、用真人形态和用户同步进度并收集需求的做法，能缩短反馈回路。我的判断是，这类直接对话本身不构成产品能力，但它能暴露团队在押注什么；对 builder 的启示是，把团队放到台前比精美的发布会有时更能校准方向，前提是后续真的要按反馈改动。
